# ギルド・クロニクル v0.355

v0.355では、旅仲間の関係が深まった瞬間を帰還報告で祝うようにしました。同じ二人の同行が5回・20回へ達した遠征では、二人の名前と新しく見られる道中・戦列の呼吸を物語調で表示します。数値補正は伏せたまま、どの組み合わせが育ったのかを見失いません。この記録は遠征履歴にも残り、読み込み時には人物・同行回数・段階名を検証します。

v0.354では、旅仲間の関係をパーティ一覧でも把握できるようにしました。隣接する隊列に戦闘連携できる仲間がいるパーティは「旅仲間 N組」と表示され、編成画面を開かなくても連携を活かせる隊を見分けられます。表示は関係の成立だけに留め、内部の補正値は引き続き伏せています。

v0.353では、育った旅仲間の関係を編成で実際に使いやすくしました。所属冒険者の一覧に、現在のパーティ内で最も長く共に歩いた相手と同行回数を一つの小型表示で出します。「編成中の旅仲間順」に切り替えると、今いる仲間と馴染みの深い待機冒険者から並ぶため、大人数の名簿でも関係を覚えている候補を探せます。名前検索から相手の名でも候補を探せますが、戦闘や道中の内部補正値は表示しません。

v0.352では、旅仲間の連携を説明文で先に教えず、実際の同行から観察日記が増えるようにしました。同じ二人が5回旅すると「言葉より先に合う歩幅」、20回では「背中を預ける、ということ」が書庫へ加わります。道中の支えや隣接隊列の手掛かりは日記調で記し、内部の確率・能力補正は明かしません。未解放の頁には最も長い同行だけを表示し、どの組を育てるかはプレイヤーが帰還記録から考えられます。あわせて、戦列連携の構造化データが実際の帰還結果・遠征履歴へ渡る経路を修正しました。

v0.351では、旅仲間の戦列連携を帰還報告と遠征履歴から振り返れるようにしました。連携した二人・並んだ隊列・関係の呼び名・同行回数を短くまとめ、内部の補正値は表示しません。戦闘ログを最初から読み直さなくても「どの並びで息が合ったか」が分かり、隊列を変えながら自分で効果を確かめられます。連携記録は探索結果と履歴へ構造化して保存し、読み込み時にも不正な組み合わせを検査します。

v0.349では、旅仲間の記憶を道中の実力へつなげました。同じ二人で遠征を重ねると、隠し道や野営、碑文などを担当する冒険者をもう一人が慣れた合図で支え、道中の成功を僅かに後押しします。効果は同行5回と20回で深まりますが、画面には確率を出さず「歩調の合う支え」「阿吽の支え」と、息を合わせた二人の名前だけを探索ログ・帰還報告・遠征履歴へ残します。固定編成だけが正解にならない小さな補正に抑えつつ、同じ仲間と旅を続ける意味を物語と攻略の両方へ持たせています。

v0.348では、保存した「旅仲間の記憶」を冒険者資料室の「遠征者の記録」で読み返せるようにしました。二人の名前、同行回数、現在見つけた記憶数をコンパクトに並べ、タップした組だけ本文を開きます。帰還報告と冒険者詳細からこの記録へ直接移動できるため、スマートフォンでも題名だけでなく場面の全文を追えます。

v0.347では、「旅仲間のひと幕」を一度きりのログではなく、二人の共有記憶として残すようにしました。未見の場面を優先して抽選し、同じ二人が20回旅した後は新しく解放された深い場面から先に見つかります。初見時は帰還報告へNEWを表示し、冒険者詳細の「共に歩いた仲間」でも相手ごとの記憶数と題名を確認できます。記憶は冒険者個人へ重複保存せず、二人の組を表す一つの記録として保持します。

v0.346では、募集で加わった冒険者同士の同行記録を探索中の短い物語へ広げました。同じ二人が5回以上遠征すると、道中で「旅仲間のひと幕」が生まれることがあります。20回以上では、長い付き合いを感じられる場面も加わります。出発時点の同行記録と遠征ごとの乱数から決まるため、帰還待ちの別パーティに影響されず、探索ログ・帰還報告・遠征履歴へ同じ出来事が残ります。物語人物には従来の専用会話を優先し、一般の冒険者だけに起きる小さな関係描写として分けています。

名もない募集冒険者同士にも、共に旅した関係が残るようにしました。同じ遠征へ参加した二人の同行回数を一組につき一度だけ記録し、冒険者詳細の「共に歩いた仲間」で長く組んだ相手を確認できます。同じ仲間と五度歩く「馴染みの同行章」と、二十度歩く「二十路の結び章」も追加し、固定編成を強制する能力補正ではなく人物の経歴として関係を育てます。

連携探索へ参加した冒険者を、道中の記録に残すようにしました。探索ログ・帰還報告・過去の遠征履歴で、得意分野を持ち寄った仲間の名前を確認できます。参加回数は各冒険者の「遠征の足跡」へ蓄積され、初回に「連携の小章」、十度目に「十図の記章」を獲得するため、追加イベントだけでなく誰と地図を作ったかが人物の経歴になります。

連携探索を長期的な収集目標へつなげました。初めて連携探索を行うと秘密実績「重なる足跡」、十度の連携探索を記録すると「皆で描いた地図」が明かされます。達成数は物語や観察記録と同じギルドの累計探索事実へ加算するため、古い遠征履歴が表示上整理されても失われず、達成した帰還報告ですぐに知らせます。

異なる探索分野に習熟した冒険者を組み合わせる「連携探索」を追加しました。二人以上の冒険者で三種類以上の道中経験を持ち寄ると、通常の探索に加えてもう一つの兆しを調べます。追加の出来事にも成功と失敗があり、戦利品だけが増える安全な特典にはしていません。発生した時だけ探索ログと帰還報告へ「連携探索」と残し、必要人数を画面へ直接示さないため、遠征記録から有効な組み合わせを試せます。

一つの得意分野だけでなく、多方面の探索経験を積んだ冒険者にも個人記章を追加しました。異なる三分野を身につけると「多芸の記章」、現在存在するすべての道中経験と開錠経験を修めると「探索者の大記章」を獲得します。達成状況は既存の個人遠征記録から自動で判定し、専用の進捗をセーブへ重複保存しないため、今後得意分野が追加された場合も最終目標が自動で広がります。

冒険者一覧でも、長い遠征で育った個性を探せるようにしました。隠し道・碑文・追跡・開錠などの得意分野を名前と同じ行へ短く表示し、探索経験の種類による絞り込みと経験順の並べ替えを追加しています。冒険者詳細の「遠征の足跡」には封印箱の開封数と身についた得意分野を道中経験と一緒にまとめ、大人数になっても戦闘能力だけではない役割から仲間を選べます。

宝箱を開けてきた冒険者にも、次の旅へ持ち越す個人経験を追加しました。鉄縁や星紋の箱を十度開けた本人が同行すると、封印箱の扱いに僅かな慣れが働きます。出発時の経験を保存するため探索途中の帰還順には左右されず、探索ログと帰還報告には「本人の開錠経験を活用」と事実だけを残します。編成画面では「開錠」の探索経験として検索・絞り込みでき、成功率や正解の職業は表示しません。

人数が増えても、道中の専門家を探して編成しやすくしました。パーティ編成の所属冒険者には、五度以上成功した「隠し道」「碑文」「追跡」などの探索経験を小さな印として表示します。探索経験の種類による絞り込みと、道中経験順の並べ替えも追加しました。観察記録と噂を照らした攻略先では、経験者がいる場合だけ名前を挙げるため、成功率や正解編成を直接見せずに誰を連れていくか考えられます。

冒険者が道中で重ねた経験を、次の旅でも活かすようにしました。同じ種類の難所を五度解決した本人が同行すると、その冒険者の慣れが同種の出来事を切り抜ける助けになります。攻略先では確率を見せず「実地で何度も解いた者がいる」と伝え、帰還報告と探索ログでは誰かの経験が役立った事実だけを残します。職業・種族・生まれによる適性、ギルドで共有した観察記録とも重なるため、長く旅をした冒険者が戦闘外でも固有の役割を持ちます。

道中で身につけた経験を、冒険者自身の長期目標へつなげました。同じ種類の難所を五度解決すると、「隠し道」「野営」「足場渡り」「碑文解読」「採取」「守護陣」「追跡」の専門記章を獲得できます。能力値を直接上げる報酬ではなく、実際に担当してきた役割を名前の横へ掲げられるため、同じ種族・職業でも遠征歴の違う冒険者として愛着を持てます。

冒険者ごとの「遠征の足跡」に、道中で解決した出来事の内訳を追加しました。隠し道を見つけた回数、碑文を読み解いた回数、守護陣を起動した回数、魔物の進路を読んだ回数などが実際に担当した本人へ蓄積されます。合計回数だけでは見えなかった斥候・野営役・術式の読み手としての経歴が残り、戦闘能力以外にも冒険者ごとの個性を感じられるようになりました。

探索ログの道中カードを読み直しやすくしました。これまで「隠された道」「古い記録」のような大分類だけだった見出しを、「魔物の足跡」「古い守護陣」など実際に起きた出来事の名前へ変更しています。成功・失敗、現地の噂との一致、共有済みの観察記録を使えたかも小さな印で並べ、確率や正解編成は明かさずに今回の旅で起きた事実を追えるようにしました。

道中イベント「魔物の足跡」を追加しました。追跡に慣れた仲間が新しい足跡から進路を読み切ると、次の一戦だけ敵へ先回りし、行動速度と命中精度が高まります。草原・坑道・火山などには足跡に結び付く噂も加わり、初遭遇と3回の成功で観察日記が二段階に増えます。戦闘の直前に得た手掛かりが実際の攻防へつながるため、純粋な戦闘力だけでなく追跡役を編成する意味が生まれました。

繰り返す遠征の道中に「古い守護陣」を追加しました。術式や祈りに通じる仲間が欠けた円環を起動すると、直後の一戦だけ一行が受ける物理・魔法ダメージを15%軽減します。遺跡・機巧地帯・雪原では守護陣に結び付く新しい噂も聞けます。初遭遇と3回の成功で観察日記が二段階に増え、既存の噂照合・知見共有・秘密実績へ同じデータ構造で加わります。

噂の照合録から、未確認の噂を追える攻略先へ直接移動できるようにしました。未知の出来事の名前や成功率は伏せたまま、現在解放済みの土地から手掛かりのある場所だけを案内します。攻略先一覧にも「未照合の噂あり／噂を照合済み」を表示し、物語を進める遠征と調査を目的にした遠征を選びやすくしました。

観察日記に「噂の照合録」を追加しました。道中でまだ見ていない兆し、遭遇したものの噂とは結び付いていない兆し、実地確認できた噂、知見まで共有した出来事を、答えや確率を明かさず一冊で追えます。攻略先でも過去に実地確認した噂が分かり、初めての照合時には資料室への報告謝礼としてギルド印章を受け取れるため、噂を追って編成を試す動機が報酬と記録の両方へつながりました。

道中の噂を初めて実地で確かめた瞬間を、探索結果の独立した発見として記録するようにしました。どの種類の噂を確かめたかは観察記録へ蓄積され、帰還報告とパーティ一覧で初確認を知らせます。すべての種類を自分の遠征で確かめる秘密実績も追加し、同じ攻略先を繰り返すだけでなく、異なる土地の噂を追う長期目標にしました。

攻略先で聞いた噂が、実際の道中に現れやすい兆しになりました。噂と同じ出来事を目撃した遠征は、帰還報告・パーティ一覧・過去の帰還記録へ「噂と一致」と残ります。ただし必ず起こる予告にはせず、別の出来事や失敗もあり得るため、噂を信じた編成がどう働いたかを探索ログで確かめる遊びを維持しています。

道中の噂と観察日記が、編成を考える手掛かりとしてつながるようになりました。噂ごとに対応する道中の出来事をマスターデータで関連付け、十分な成功記録が集まった後だけ、現在のパーティに記録と似た経験があるかを文章で照合します。適職名・成功率・正解編成は表示せず、未知の噂は未知のまま残るため、最初は探索ログから学び、知見を共有した後は別の編成を試す判断へ活かせます。

攻略先の詳細に「道中で聞いた話」を追加しました。地形ごとに起こりやすい探索上の出来事を、成功率や推奨職業を直接示さない短い噂として読めます。噂は攻略先ごとに固定されるため、編成を変えながら探索ログと見比べ、隠し道・採取・碑文・危険な足場などへの相性を自分で推測できます。

戦闘外の探索を長期目標へつなぐ、3つの隠し実績を追加しました。すべての道中イベントとの遭遇、全知見の共有、すべての封印箱の開錠記録がそれぞれ実績になります。必要数はマスターデータから自動算出するため、今後イベントや宝箱を増やしても実績条件が古い件数のまま残りません。

探索中に「素材の痕跡」を追加しました。狩り・採取・地形読みに通じる冒険者が痕跡を追うと、そのダンジョンに棲む魔物由来の製作素材を持ち帰ります。素材の種類と数は旅ごとに変わり、担当者、成否、獲得品は探索ログと帰還報告へ残ります。成功を3回重ねると採取帳が全パーティへ共有され、観察日記にも遭遇・習熟の頁が増えます。

探索中に「忘れられた碑文」を追加しました。魔術・古語・祈りに通じる冒険者が欠けた文字を読み解くと、戦闘以外からも一行が経験を得ます。誰が解読を試みたかは探索ログと帰還報告へ残り、成功を3回重ねると拓本の知見が全パーティへ共有されます。初遭遇と知見完成時には観察日記が増え、数値を直接見せずに相性を読み取れます。

冒険者個人の「遠征の足跡」に、道中の難所を解決した回数と封印箱を開けた回数を加えました。最初と10回目にはそれぞれ探索者向けの記章を獲得します。戦闘能力だけでなく、実際の探索で隠し道を見つけたり宝箱を開けたりした履歴が人物の経歴として残り、表示する記章にも選べます。

帰還報告とパーティの遠征履歴で、戦闘外の働きも冒険者個人へ記録するようにしました。隠し道・野営・危険な足場を成功へ導いた時や、鉄縁・星紋の箱を開けた時に担当者を「道中の難所を解いた」として表示します。攻撃・回復・耐久だけでは目立ちにくかった斥候や探索役にも、その遠征で果たした役割が残ります。

宝箱を開けた経験がギルド全体へ蓄積されるようにしました。同じ種類の箱を3回開けると開錠記録が完成し、以後に出発する別パーティも僅かに開けやすくなります。鉄縁・星紋の箱へ初遭遇した時と、鉄縁の知見が完成した時には観察日記が追加され、成功した編成を自分で読み解けます。出撃済みの探索は出発時の知識を保持するため、帰還順で結果が変わりません。

鉄縁や星紋の宝箱には、それぞれ錠や魔法封印を解く探索判定を追加しました。盗賊・狩人系の観察眼、前衛の突破力、魔術師系の知識などから最も適した一人が自然に挑み、成功すれば本来の中身を獲得します。開けきれなくても僅かな所持金は回収でき、探索ログには誰がどう対処したか、帰還報告には開封数と一部回収を残します。確率や正解の職業は画面へ直接表示せず、旅の記録から相性を推測できます。

探索中の宝箱を「古びた木箱」「鉄縁の宝箱」「星紋の宝箱」の3段階にしました。希少な箱ほど装備が入る可能性と所持金が増え、難しい探索地や高難易度ほど上位の箱を見つけやすくなります。探索ログだけでなく帰還報告にも箱の種類と中身をまとめ、道中の発見に起伏を持たせました。

装備候補に、装着後の組合せ進行と新しく発動する効果を表示するようにしました。「1 → 2 / 3」のように現在と装着後を並べ、節目を越える品は強調します。おすすめ順でも組合せ効果を発動できる候補を優先するため、数値だけでなく一式をそろえる判断がしやすくなります。

所持品とキャラクターの装備候補に「装備組合せ」の絞り込みを追加しました。組合せ装備全体、または発見済みの組合せ名から選び、そろえたい一式だけを探せます。未発見の組合せ名は表示しないため、収集の手掛かりを増やしつつ将来の発見は隠します。

探索ログの出発記録で、発動している装備組合せを冒険者ごとに確認できるようにしました。組合せ名、そろえた種類数、発動効果を一行にまとめ、通常の装備スキル欄には重複表示しません。出発時点の組合せを探索へ保存するため、帰還までの間に装備を変更しても過去のログは変化しません。

鍛冶屋で組合せ装備を初めて製作した時も、完成表示の中で組合せ記録の進展を確認できるようにしました。発見数の変化に加え、2種類・3種類の節目を越えた場合は新しく判明した効果を表示します。探索ドロップと製作で同じ判定を共有するため、今後組合せや必要数を増やしても通知の食い違いが起きません。

帰還時に新しく見つけた装備が既知の組合せを進めた場合、パーティ一覧と帰還報告で知らせるようにしました。何種類目を発見したかを以前の数と並べ、2種類・3種類の境目を越えた時は新しく判明した組合せ効果もその場で表示します。帰還報告からアイテム図鑑の組合せ記録へ移れるため、次に探す一品へ自然につなげられます。

鍛冶屋の組合せ装備へ小さな「組合せ」印と収集状況を追加しました。レシピを開くと、発見済みの系統品、未発見品、次の組合せ効果までに必要な種類数を確認できます。まだ一品も持ち帰っていない組合せは名称と他の品を伏せ、製作後に図鑑と同じ段階で情報が開きます。

鍛冶屋で作る序盤4系統の装備に「装備組合せ」を追加しました。同じ系統の異なる装備を2種類身につけると、風渡り・坑道・古代兵・星落ちそれぞれの小さな固有効果が発動します。同じ雛形を複数装備しても種類数は増えません。装備候補には所属する組合せを、キャラクター能力欄には現在の進み具合と発動中の効果を表示し、装備変更後の能力差にも即座に反映します。定義は `data/equipmentSets.js` に分離しているため、後の章の装備組合せや3種類以上の段階効果もデータ追加だけで拡張できます。

アイテム図鑑へ「装備組合せの記録」を追加しました。系統品を一つ入手すると組合せ名と発見済みの品だけが開き、必要数をそろえるまでは効果名を伏せます。異なる品を実際に見つけた段階で効果の名称と内容が記録され、全品発見した系統も確認できます。未発見の品名や未遭遇の組合せはまとめて隠すため、収集目標を作りつつ先の戦利品を明かしすぎません。

各冒険者の「遠征の足跡」に個人記章を追加しました。出撃、攻略、戦闘突破、累計ダメージ、回復、耐久、会心など、実際に積み重ねた個人記録から自動で判定します。獲得した記章と次に近い記録を冒険者詳細で確認でき、能力値や報酬には影響しません。記章はマスターデータとして独立し、セーブには重複保存しないため、今後新しい記録を追加しても既存冒険者へ自動反映されます。

個人記章を獲得した瞬間は帰還報告にも表示します。誰がどの記章を得たかを確認し、そのまま対象冒険者の「遠征の足跡」へ移れます。獲得通知は遠征前後の記録差から作るため、すでに持っている記章を帰還のたびに繰り返し表示しません。

装備や編成を変えた成果を感じやすくするため、一遠征の与ダメージ・回復量・生還時の被ダメージが自己最高を更新した場合も帰還報告へ表示します。以前の値と新記録を並べ、記録を更新した冒険者の足跡へ直接移動できます。

獲得した個人記章から一つを「表示する記章」に選べるようにしました。選択した記章は冒険者一覧・詳細・パーティ一覧の名前に添えられ、能力値を変えずに長く活躍した冒険者の個性を残せます。未獲得の記章は設定できず、いつでも付け替え・解除できます。

冒険者資料室に「遠征者記録」を追加しました。遠征回数、攻略回数、突破戦闘数、一遠征の与ダメージ・回復量・生還時被ダメージを冒険者同士で比較でき、記録行から本人の足跡へ移動できます。数値は保存済みの個人戦績から都度集計し、順位専用のセーブデータを持ちません。

日々の攻略先選びに小さな変化を付ける「旅人の噂」を追加しました。現在入れる探索地の一つへ、商隊・旅学者・鍵師・鍛冶師にまつわる噂が現れ、お金・経験値・品物の発見・品質のいずれかに恩恵があります。具体的な倍率は画面へ出さず、噂の文章と帰還結果から手応えを確かめる構成です。噂と効果は出発時に保存されるため、日付や物語進行が変わっても探索途中の内容は変化しません。

物語NPCを編成した探索では、探索ログに一度だけ「道中のひと幕」が残るようになりました。一人ならその人物らしい仕草、対応する二人が同行していれば個人描写より二人の掛け合いを優先します。場面には登場人物の専用立ち絵・名前・肩書きを添え、探索中と帰還後のどちらでも誰の出来事か一目で分かります。一度見た場面は人物録の「旅の記憶」へ蓄積され、未見の内容や出現条件は表示しません。探索開始時の記録から同じ内容を再現するため、途中経過と帰還後の履歴で内容が変わらず、戦闘結果や宝箱の抽選にも影響しません。

旅の記憶に連動する秘密実績を追加しました。最初の人物場面、二人の掛け合い、複数の旅の記憶という三段階を現在の記録から自動判定し、達成するまでは名前・条件・総数を伏せます。報酬や能力値は付けず、普段と違う同行者を試した歩みだけを記念する要素です。

遠征によって初めて達成した実績は、帰還報告に名称を表示するようになりました。秘密実績も達成した瞬間に初めて内容が明かされ、そのまま冒険者資料室の実績記録へ移動できます。実績判定は帰還前後の状態差から行い、以前に達成済みの実績を毎回通知しません。

初めて目撃した「旅の記憶」も帰還報告へ独立して表示します。場面名と登場したNPCを短く確認でき、人物録へ直接移って本文を読み返せます。同じ文章を再び見た遠征では新規記録として扱わず、帰還報告を繰り返し長くしません。

旅の記憶は、同じ人物または対応する二人を編成した際に未見の文章を優先して選ぶようにしました。対象の場面をすべて見た後だけ既読場面が再登場します。出発時点の人物録を遠征へ保存するため、探索中に別パーティが先に帰還して記録を増やしても、表示中の探索ログと帰還後の内容は変わりません。

人物同士の掛け合いを4組追加し、特定の固定ペア以外にも同行編成を試せるようにしました。初めて見た二人の場面は、未発見の組み合わせを伏せたまま人物録の「同行の記録」へまとめられます。人物ごとの旅の記憶を開かなくても、誰と誰の関係を発見したかを立ち絵と場面名で振り返れます。

同じ二人の掛け合いをすべて見届けると、一度だけ「同行の縁」が結ばれてギルド印章を1個獲得します。必要回数や未発見の組み合わせは事前に表示せず、帰還報告で関係が深まった瞬間と記念品だけを伝えます。達成状態は既存の旅の記憶から判定するため、関係専用の重複したセーブ項目を持ちません。

人物録の「同行の記録」は、途中まで見た関係を篇数、すべて見届けた関係を「縁が結ばれた」と区別して表示します。同行の縁を4組・8組と結んだ歩みには秘密実績を追加し、達成するまでは名前・条件・残数を表示しません。実績も旅の記憶から都度判定するため、専用の進捗データは不要です。

探索中の戦闘外イベントとして、隠し通路・安全な野営地・崩れやすい足場を追加しました。1回の出撃に一場面だけ発生し、隠し通路ではお金、野営では戦闘間の回復、危険な足場では非致死の負傷が起こります。盗賊や狩人などの探索役、僧侶などの治療役、戦士などの前衛役がいると対応する出来事で良い結果になりやすい一方、確率や適職は画面に直接表示せず、ログに残る行動から推測できます。抽選は戦闘・宝箱・人物場面と別の乱数列を使い、出発時の編成記録から途中表示と帰還結果を同じ内容で再現します。

パーティがバックグラウンドで帰還しても、閲覧中の画面本文を自動で描き直さないようにしました。探索・戦闘ログ、開いている品物やレシピ、検索入力、モーダル、スクロール位置を維持したまま、帰還通知、所持金、探索状態、未読バッジだけを更新します。ただしパーティタブの一覧は運行状況を確認する画面なので、絞り込みとスクロール位置を保ったまま帰還結果を即時反映します。それ以外の画面では、新しい戦利品や帰還結果を次の画面移動または操作確定時に通常表示へ反映します。

物語NPCの最大登録人数も `GameData.registry.config()` 経由で登録するようにしました。これでデータファイルが `GameData.config` を直接書き換える例外がなくなり、設定の重複・読み込み漏れ・実行中の変更を共通処理で検出できます。

装備スキル、レシピ、探索地、物語、敵ドロップ、出自スキル、NPCなどの主要なID参照を、マスター確定前に自動検証する仕組みを追加しました。存在しない装備・敵・スキル・シーンを指定したデータは、参照元を示すエラーとしてゲーム開始前に検出されます。

マスターの全テーブル名を `GameData.masterMeta.tables` に分類別で集約しました。登録API・確定処理・検証が同じ一覧を参照し、宣言したファイルの読み込み漏れがある場合はゲーム開始前に不足テーブル名を示して停止します。

全マスターデータの読み込み完了後に `GameData.registry.finalize()` を実行し、エンティティ・設定・関係・派生データを再帰的に固定するようにしました。ゲーム開始後の誤代入や遅延登録を即座に検出し、マスターとセーブ状態の境界を保ちます。

装備・モンスターの補完済み戦闘能力と、難易度別モンスタードロップの生成結果を `GameData.registry.derived()` で一括登録するようにしました。生成途中の参照表を公開せず、同じ参照表の二重生成も登録時に検出します。

追加性能抽選、探索イベント、品質抽選表、定期依頼、商店進行、スキル分類も `GameData.config` へ移しました。これで調整用の設定値がマスタールートへ直接置かれず、エンティティ・関係・生成済み参照データ・設定の境界が揃いました。

元データから生成する参照用データへ `GameData.registry.derived()` を追加しました。装備種別マスターから作る武器種名・防具種名の一覧を `GameData.derived` へ移し、手入力のマスターや設定値と区別しました。

種族・職業・生まれと装備種の適性、装備種ごとの強化スキル、出自ごとの習得スキルを `GameData.relations` へ移しました。能力本体と「何を付与するか」の関係が分かれ、職業や装備種を追加する際の参照を一つの関係層から検証できます。

施設データを、ID付きの施設本体 `GameData.facilities` と、表示順・強化枠・強化費用などの共通設定 `GameData.config.facilities` に分離しました。新施設の増設時に既存IDの重複を検出でき、施設個別データと全体ルールを混在させずに拡張できます。

募集費用、希望項目、応募人数、名前候補などの募集設定を `GameData.config.recruitment` へ移しました。応募者・雇用状態として保存されるデータや、ID付きの得意分野マスターと分離し、募集条件の調整値を一か所から参照します。

パーティ拡張、装備強化、募集条件が章データの解放文を直接書き換えていた処理を廃止しました。追加の解放内容は `chapterUnlockAdditions` 関係データとして登録し、物語表示時に合成するため、章本体を読み込み後に変更しません。

転職条件、パーティ枠進行、装備強化上限も `GameData.config` へ移しました。また、レシピ・物語章・依頼は各ファイルで空配列を作らず、順序付き登録APIが登録先を初期化するように統一しました。

マスターデータ本体とは別に、数値調整用の設定を登録する `GameData.registry.config()` を追加しました。装備バランス、成長曲線、戦闘行動、通常戦利品、超レア抽選の設定を `GameData.config` に集約し、同じ設定を複数ファイルから上書きできないようにしました。

アクセスコード、探索難易度、募集時の得意分野に加え、実績と観察日記も共通レジストリへ移しました。順序付きデータは登録先の配列を各ファイルで事前作成せずに済むようになり、後から実績や記録を分割追加してもID重複を一括検証できます。

品質、装備スキル、モンスタースキル、超レア称号も共通のエンティティ登録へ統一しました。戦利品や戦闘を拡張する際に、同じIDの品質・スキル・称号を別ファイルから誤って再定義すると読み込み時に停止し、途中まで登録された状態も残りません。

装備種別、属性、状態異常、生物分類、キャラクター画像も重複検査付きのエンティティ登録へ統一しました。これらは装備・戦闘・特攻・募集UIから広く参照されるため、IDの再利用や一部だけ上書きされた不整合を読み込み時に検出できます。

職業・種族・生まれの基礎マスターも `GameData.registry.entities()` 経由へ統一しました。将来の職業・種族追加で既存IDを誤って再利用した場合は読み込み時に停止し、能力補正や習得スキルが別の出自へ上書きされることを防ぎます。

基礎装備・基礎モンスター・基礎探索地・基礎物語・基礎レシピも、完成したローカル定義を登録APIへ渡して公開する方式へ統一しました。追加章だけでなくゲーム開始時から存在するIDも同じ重複検査を通るため、基礎マスターと追加コンテンツの登録規則に例外がなくなりました。

モンスター・冒険者種族と「獣／竜／不死」などの分類対応を、トップレベルの疑似マスターから `GameData.relations.monsterFamilies`／`adventurerFamilies` へ移しました。分類は本体ではなくID同士の関係として重複検査付きで登録され、特攻計算・敵ドロップ傾向・図鑑の参照窓口を `MonsterLoot` に統一しています。

基礎スキルと、職業・種族・生まれから自動生成する初期／成長スキルを、ローカルで完成させてから `GameData.registry.entities("skills", ...)` へ一括登録する構造へ移しました。属性・状態異常・獲得効果の追加中や生成途中の状態は公開されず、基礎スキルと生成スキルのID衝突も登録前に検出されます。

章・レシピ・依頼のような順序付きマスターへ `GameData.registry.entityList()` を追加しました。第4〜15章とクリア後領域はレシピ・章定義を直接 `push` せず、一括検証後に登録します。依頼掲示板の自動生成依頼も完成した配列を一度だけ登録するため、章やレシピを増やした際のID重複で一部だけデータが残りません。

残っていた関係テーブルの直接置換を廃止しました。難易度別モンスタースキル、難易度別固有ドロップ調整、探索地の編成制限も `GameData.registry.relations()` 経由で登録します。これで装備スキル、敵ドロップ、NPC物語、探索地物語を含むすべてのオブジェクト型関係データが、反映前の重複検査を通るようになりました。

物語NPC関連の定義を登録APIへ統一しました。NPC本体、固有スキル、成長段階、物語上の役割、シーン差し替えを完成させてから一括登録し、加入・成長イベントには配列型関係専用の `GameData.registry.relationList()` を使います。NPCや個人ストーリーを追加した際も、既存IDの上書きや同じイベントの二重登録を読み込み時に拒否します。

探索地の冒頭・発見シーン参照を、探索地本体から `GameData.relations.dungeonStoryLinks` へ分離しました。探索地は攻略条件・敵・報酬などの探索定義に専念し、物語との接続は専用の関係表から解決します。通常章とクリア後領域で同じ登録・重複検査を使い、物語追加が探索地マスターを書き換えない構造になりました。

商店が自動生成する高Tier装備と、全探索地から生成する冒頭・発見シーンもエンティティ登録API経由へ統一しました。雷鳴の天文塔は基礎探索地マスター内で最初から完成した状態を持ちます。生成コンテンツも固定コンテンツと同じ重複検査を受けるため、将来の装備・物語追加が既存IDを上書きしません。

関係テーブルにも重複安全な `GameData.registry.relations()` を追加しました。通常素材・固有ドロップ・固定装備スキルはすべて登録前に一括検証され、別ファイルが同じ関係IDを黙って上書きできません。商店は自動生成した装備だけを所有し、木の剣など既存装備の正式スキルは `itemSkills.js` だけが登録します。

通常素材ドロップをモンスターの戦闘データから分離しました。素材表は `GameData.relations.monsterMaterialDrops` に集約し、戦闘・探索時間計算・鍛冶屋・図鑑・資料室は `MonsterLoot.materialDrops()` から共通参照します。モンスター本体は能力・耐性・行動だけを持ち、通常素材・固有ドロップ・難易度固有ドロップはそれぞれ独立した関係表で管理します。

基礎装備と基礎モンスターも、作成途中のマスターを公開してから種類・ドロップ・弱点・大技を後付けする構造を廃止しました。ローカルな定義と関係表をすべて合成してから `GameData.items`／`GameData.monsters` を一度だけ公開し、読み込み途中の不完全な定義や後付け漏れが発生しない構造へ揃えています。

章4〜15とクリア後領域のモンスター素材表を、登録済みの敵へ後付けする方式から、敵本体と合成して一度だけ登録する方式へ変更しました。第4章の推奨レベル・難易度・報酬・敵倍率も登録前に解決し、追加コンテンツの敵・探索地は登録後に書き換えません。構造検査テストにより、直接代入や後付け更新が再び混入することを防ぎます。

章・クリア後コンテンツの追加定義を、重複を検知する `GameData.registry.entities()` 経由の登録へ統一しました。登録先・オブジェクトのキー・定義内IDの一致を確認し、既存IDへの上書きをエラーにします。一括登録は全件の検証が済んでから反映するため、不正な定義が混じっても一部だけマスターへ残りません。

称号モンスターのドロップ表を、手書きの個別調整と通常表からの自動生成に分離しました。個別調整は `GameData.relations.monsterDifficultyDropOverrides`、全モンスターの解決済み表は `GameData.derived.monsterDifficultyDrops` に置きます。これにより、調整元と計算結果が同じプロファイルへ混在せず、魔境・神域の追加ドロップをモンスター単位で安全に差し替えられます。

称号モンスターの固有スキル付与をドロップ・能力補正から分離しました。スキル本体は `GameData.monsterSkills`、モンスター・難易度との対応は `GameData.relations.monsterDifficultySkillGrants`、固有ドロップの個別調整と解決結果は専用の関係表・派生表が担当します。神域で魔境スキルも継承する処理は解決側へ集約し、定義ファイルが別マスターを後から書き換えません。

固定装備スキルの旧形式フォールバックを削除しました。装備本体の `skillIds` は読み取らず、すべての固定スキルを `GameData.relations.itemSkillGrants` だけから解決します。未定義の装備が追加された場合は読み込み時に明示的なデータエラーとなるため、スキルなしのまま気付かず登録されることもありません。

第1～3章の基点ダンジョンと章冒頭物語を、後続ファイルから上書きする構造を解消しました。草原・洞窟・古代遺跡・天文塔は `data/dungeons.js`、章冒頭文と章目標は `data/story.js` が最終形を直接所有します。`earlyExpansion.js` は追加探索地・敵・途中物語の新規登録だけを担当し、読み込み順を変えても既存定義が変質しないことを専用テストで検証します。

装備・モンスターの省略可能な戦闘能力を、マスター本体へ後付けする方式から `GameData.derived` の参照用データへ移しました。装備は `Items.template()`、モンスターは難易度解決処理を通すことで常に補完済みの能力を参照します。元の定義は変更されず、明示した能力値を優先するため、追加データの意図が読み込み順で失われません。

職業・種族・生まれ・モンスターへ別ファイルから能力や耐性を後付けする処理を整理しました。出自の能力補正・属性相性・状態耐性は各出自定義へ、敵固有の属性・耐性・状態攻撃は各モンスター定義へ移動しています。省略可能な敵の魔法能力・命中・回避だけを `GameData.derived.monsterCombatStats` で補完し、敵本体を書き換えずに難易度計算へ渡します。

モンスターの戦闘能力と固有ドロップ表を分離しました。通常難易度の固有素材・固有装備は `GameData.relations.monsterSignatureDrops` に集約し、モンスター本体にはHP・攻撃・耐性・行動などの戦闘情報だけを置きます。魔境・神域はこの通常表を参照して上位表を生成するため、下位ドロップを包含する既存仕様を保ったまま追加・検証しやすくなりました。

装備テンプレートと固定装備スキルの関係を分離しました。装備本体は基礎性能・種別・入手属性だけを持ち、付与スキルIDは `GameData.relations.itemSkillGrants` へ集約しています。商店の自動生成装備やクリア後装備も同じ関係表へ登録されるため、装備追加時の参照切れや重複を一括検証できます。

マスターデータ構造を第32版へ整理しました。`data/masterSchema.js` を起点に、各エンティティ本体、順序付きエンティティ、システム設定、ID同士の関係、共通ルールから作る参照用データを分離しています。NPCの固有スキル・成長段階・物語上の登場、物語イベントの発火条件、探索地の編成制限・物語接続、モンスターや冒険者種族の分類、モンスターの通常素材ドロップは `GameData.relations` に集約し、章・探索地・シーン・敵本体を後から書き換えない構造へ変更しました。

物語効果は一意なIDを持つ `storyTriggers` として定義します。章開始・章達成・探索地解放・発見・攻略の条件を共通形式で扱えるため、今後NPCの加入、個人ストーリーによる強化、特殊解放を同じ仕組みで追加できます。シーン本文や主人公・同行者の差し替えも `storySceneOverlays` に分離しました。

一部の任意攻略ダンジョンへ、データ定義式の編成制限を追加しました。「指定種族だけで編成」「指定NPCだけで出撃」「指定NPCを含む編成」の3形式に対応し、攻略先カードと出撃欄で条件の達成状態を確認できます。条件外のままでは個別出撃・一斉出撃とも開始されず、該当する冒険者名または不足しているNPCを表示します。

最初の対象は、竜人のみで挑む「古灰竜の火口」、ティオ単独で挑む「忘却巨人の墓」、ノアを含む編成で挑む「世界傷の氷河」です。いずれも本編進行に不要な任意攻略ダンジョンのため、特殊編成を作らなくても物語は進められます。今後は `data/dungeonPartyRestrictions.js` へ規則を足すだけで対象を増やせます。

物語NPCは、主人公・同行者として初登場する章が始まった時点でギルドへ加入するようになりました。加入章の攻略を終えるまで待たず、その人物を直ちに編成・装備できます。人物録は未遭遇の人物を伏せ、加入後に立ち絵・人物像・物語テーマ・関係した章・現在の固有スキルを記録します。

NPC専用の物語成長段階を追加しました。章の開始・達成、探索地の解放・発見・攻略を契機に段階を進められ、既存の固有スキルの置き換えと新しい固有スキルの追加をデータで定義できます。最初の例として、第14章達成時にノアが星核を取り戻し、固有呪文が変化して新しいパッシブを習得します。通常のレベルや転職とは独立しているため、今後は各NPCの個人ストーリーへ同じ仕組みを拡張できます。

物語加入NPCを第2章から段階的に8人まで追加しました。ミナ、エレナ、ガルム、シア、ティオ、リゼ、カイ、ノアがそれぞれ加入章の主人公となり、後の章でも知識や過去を通じて物語を動かします。ホームと物語の振り返りには、各場面の主人公・同行者・立ち絵が表示されます。

物語加入者は `data/companions.js` に人物本体と、`GameData.relations` 配下の固有スキル・成長段階を持ちます。`data/companionStories.js` は加入章・活躍章・物語トリガー・シーン差分だけを定義します。現在の上限8人は `GameData.config.companions.rosterLimit` に明示しているため、今後は上限値を変更して同じ形式のNPCを追加できます。マスターデータには段階ごとの追加・置換スキルを置き、セーブには現在の段階IDだけを保存します。`node tests/story-companions.test.js` で初登場時の加入、段階成長、固有スキルの変更、転職後の保持、重複防止、セーブ検証を確認できます。

所持品の素材台帳を20種類単位のページ表示にしました。素材が今後増えても台帳を開いた時の縦幅を一定に保ち、ページ切り替え後は素材台帳の見出しへ戻ります。名前検索中は該当結果だけをページ計算します。

所持品の素材台帳へ素材名検索と「所持数が多い順／名前順」の並べ替えを追加しました。検索中も全体の種類数・総数は見出しに残り、条件変更や解除後も素材台帳の開閉状態とスクロール位置を維持します。

所持品で探索ドロップの自動売却を有効・無効にした時に、開いていた自動売却欄とスクロール位置を維持するようにしました。設定を切り替えた直後に欄が閉じたり、装備一覧の先頭へ戻されたりしません。

鍛冶屋で装備を製作すると、抽選された品質・実性能・固有スキルを画面上部へすぐ表示するようにしました。レシピ一覧と探索目標からの絞り込みは維持され、完成品は「所持品で確認」から同じ装備種・品質へ絞った新しい順の一覧で確認できます。

探索目標から鍛冶屋を開いた時は以前の検索・絞り込み条件を解除し、関連レシピを欠けずに表示するようにしました。入口に「製作可能」「素材・資金不足」の件数を表示し、製作可能なレシピを先に並べるため、集めた素材で今何を作れるかをすぐ判断できます。

探索目標の品を持ち帰った帰還報告から、その素材を使用する解放済みレシピへ直接進めるようにしました。累計必要数を満たすとボタンが「集めた素材で製作へ」に変わり、戦利品確認から鍛冶屋まで画面を探し直さず移動できます。

探索目標の入手先を開く時、待機中の編成済みパーティが複数ある場合は使用する隊を選べるようにしました。選択前は各隊に保存された攻略先を変更せず、現在の攻略先も選択肢へ併記します。選んだ後も出撃は自動で始まらないため、複数隊の計画を誤って上書きしにくくなります。

素材を探索目標にしている間は、パーティ一覧からその素材を使う解放済みレシピだけを鍛冶屋で確認できるようにしました。目標達成後はボタンが「製作へ」に変わり、素材収集から装備製作へ迷わず戻れます。通常の図鑑目標やレシピの解放状態は変えません。

パーティ一覧の探索目標へ、現在挑戦できる入手先を最大4件まで直接表示しました。候補を選ぶと待機中で編成済みのパーティへ攻略先を設定し、そのまま出撃先指定画面を開きます。探索は自動で始まらないため、難易度や探索時間を見てからプレイヤーが出撃を決められます。

パーティ一覧の上部へ探索目標を常設表示しました。対象品、累計進捗、現在挑戦できる範囲で入手記録のある探索地数を確認でき、「攻略先を探す」から選択中のパーティの出撃先指定へ、「図鑑で変更」からアイテム図鑑へ直接移動できます。

鍛冶屋の解放済みレシピで不足している素材を、その場から探索目標へ設定できるようにしました。目標の必要数には現在の不足分が入り、以前と同じ素材でも新しい製作計画として進捗を0から始めます。レシピで名前を知った素材は、まだ一度も入手していなくても目標にできます。

探索目標へ1〜999個の必要数を設定できるようにしました。対象品を持ち帰るたびに図鑑の累計進捗が増え、攻略先・帰還報告・パーティ一覧でも現在数を確認できます。必要数を達成しても目標は残るため、そのまま収集を続けるか、図鑑から別の品へ切り替えられます。

探索目標を設定して出撃し、その品を持ち帰った時は、帰還報告へ「探索目標を発見」と数量を専用表示するようにしました。パーティ一覧でも直近の目標達成を一目で確認できます。探索中に図鑑の目標を変更しても出撃時の目標で判定し、達成後も自動解除しないため、同じ品を続けて集められます。

発見済みの品をアイテム図鑑から一つ「探索目標」に設定できるようにしました。パーティの攻略先選択では、その品を宝箱や魔物から持ち帰った記録がある探索地だけに印を表示します。確率や推奨編成は明示せず、図鑑で得た知識をもとにプレイヤー自身が行き先を試せる導線です。

アイテム図鑑へ「名を持つ逸品の記録」を追加しました。8種類の超レア称号は実際に獲得するまで名前を伏せ、発見後は称号名・固有技能・説明をいつでも読み返せます。発見記録は装備を手放しても残り、新称号は資料室の新着件数と帰還報告へ表示されます。

探索で超レア称号付き装備を獲得した時は、通常の戦利品と分けて帰還報告へ特別表示するようにしました。パーティ一覧にも「超レア」の獲得数を表示し、報酬内訳では称号名を確認できます。`ULTRA`、初発見の `NEW`、最高品質更新の `BEST` は同時に成立してもそれぞれ判別できます。

探索で既知の装備について過去最高の品質を更新すると、帰還報告へ `BEST` と「最高品質更新」を表示するようにしました。最高品質はアイテム図鑑へ永続記録されるため、その個体を後で売却・分解しても記録は残ります。初入手の `NEW` とは分けて扱い、パーティ一覧でも更新数と該当装備を短く確認できます。

今後の装備追加で重量効率の逆転を見落とさないよう、装備種ごとのTier推移を確認する監査を追加しました。汎用品は次Tierで一度でも低下するとテストで検出し、自動補正が2.5倍を超える極端な元データも検出します。製作品・固有品のスキルや特殊効果による個性は別に保ちます。

鋼の剣を初めて入手すると、冒険者資料室の観察日記に「重さ八の袋に、剣をどう詰めるか」が追加されます。数式や内部指標は示さず、荷役係が装備の重さ・役目・技能を比べた日記として読めます。入手後に売却しても発見記録は失われません。

低Tierの軽量装備を多数積む方が、同じ重量帯の高Tier装備より強くなりやすい問題を、重量1あたり性能で調整しました。装備可否は画面に表示される重量の合計だけで判断します。汎用品は各装備種の直前Tierの実効値を基準に、Tierが1上がるごとに役割性能／重量が4%以上高くなります。基準を既に満たす装備は変更せず、下回る装備だけを実効ステータスで底上げします。商店・鍛冶屋・図鑑・所持品・装備比較・戦闘は、すべて同じ補正後の値を使用します。

技・呪文・回復の再使用間隔を、従来のカテゴリ共通10ターンからスキルごとのクールタイムへ変更しました。単体の基本技・構え・単体回復は8〜12ターン、範囲技や上位技能は14〜30ターンを基準にしています。使用済みのスキルだけが待機状態になるため、同じ分類の別スキルを続けて選ぶことができます。再使用可能ターンとCTは戦闘ログへ記録し、装備画面・募集画面・冒険者資料室でも各スキルの詳細を開くと確認できます。

ギルドの恒久的な拡張費用を見直しました。パーティ増設は第2隊10,000G、第3隊100,000Gから始まり、以後は500,000G、2,000,000G、8,000,000G、30,000,000G、コード枠100,000,000Gと段階的に増加します。施設強化にも素材だけでなく所持金が必要になり、高い設備レベルと後発施設ほど費用が増えます。施設強化をリセットしても、消費した所持金と素材は返却されません。

冒険者の雇用費も、職業・種族・初期能力の差が資金計画に反映される水準へ引き上げました。ただし序盤の立ち上がりを止めないよう、最初の3人には250G、150G、50Gの「新設ギルド支援」を順番に適用します。最初の1人は初期資金で雇用でき、2〜3人目は序盤探索の収益で揃えられる設計です。

序盤の装備可能重量を見直しました。これまでは全Tier装備の平均重量6.975をLv.1から使っていたため、重量1〜2の初期装備を想定以上に積めました。装備可能数が増えるレベル表は変えず、1枠ぶんの基準重量をLv.1の3から始め、Lv.20で5、Lv.49で6.25、Lv.89で従来の6.975へ合流させます。Lv.1の基礎上限は約57%減りますが、高レベル帯の上限は従来どおりです。職業・種族・生まれの重量補正と、軽量品質による選択肢は維持しています。

自動バランス検証に `--preparation progression` を追加しました。従来の標準品質・無強化による最低条件とは別に、第9章から「出来の良い」、星後領域から「手になじむ」、第5章以降はその時点の強化上限の1/4を使う保守的な進行相応装備で全章を検証できます。後半章を無強化装備で一律0%と判定して敵だけを弱体化する誤調整を避け、装備更新後にも突破不能かを切り分けられます。

第1章終盤の推奨Lv帯では、僧侶が最初の回復技能をまだ習得しておらず、回復役を入れた編成が回復なし編成より大幅に不利になる問題がありました。僧侶の初期スキル4枠のうち「職能発揮」を弱い単体回復「応急祈祷」へ変更し、Lv.1から回復役として行動できるようにしました。Lv.10の「治癒」は、従来どおりより強い職業技能として習得します。月牙狼の巣穴を固定条件で再検証し、均衡型が実際に回復を行い、編成逆転の警告が解消されることをテストしています。

ギルド施設は、達成済みの本編1章につき各施設で1回分の共有強化枠を得ます。強化枠は生産量・保管庫・作業速度へ自由に配分できます。施設ごとのリセットでは全系統をLv.1へ戻して枠を振り直せますが、使用済みの所持金と素材は返却されません。保管済みの生産物は維持します。

手動テスト前のバランス崩れを見つけやすくするため、自動バランス検証に探索地単位の `--dungeon` 実行と、「回復なし編成が均衡型を20pt以上上回る」編成逆転警告を追加しました。勝率だけでなく、役割を加える意味が失われていないかを検出できます。

パーティ一覧の直近報酬で、装備・素材の要約をタップすると省略された品を含む全件と数量をその場で確認できるようにしました。閉じている時の一覧の高さは従来どおりです。

スマートフォン全体の情報密度を見直しました。検索・絞り込みは必要な時だけ開く1行メニューにまとめ、画面上部・カード・資料室・物語・施設の余白と説明量を圧縮しています。ボタンのタップ領域は保ったまま、一覧と主要操作へ少ないスクロールで到達できます。

## 自動バランス検証

冒険者資料室に「実績の記録」を追加しました。雇用人数、パーティ編成、章・ダンジョン攻略、星後領域、任意攻略、神域踏破、討伐・収集、超レア装備、施設強化を21個の中長期目標として確認できます。未到達の任意ボス等は秘密実績として名前と条件を伏せます。実績は既存のセーブ内容から毎回自動計算するため、マスターデータとセーブデータを混在させず、セーブ形式の変更もありません。定義は [data/achievements.js](data/achievements.js)、判定は [js/achievements.js](js/achievements.js) に分離しています。

本編完結後のやり込みを、本編とは別の `kind: "postgame"` を持つ章として追加できる構造にしました。星後領域I「五界の標」は、星後の神域攻略後に灰の海、玻璃峡谷、世界皮菌庭、無響鉄都、遠界観測座を順に巡る推奨Lv110〜115の遠征です。全5攻略地と任意高難度、新しい敵16種、素材8種、通常・製作・ボス固有装備9種、連続する後日談を収録しています。道中3地点の攻略ごとに、その時点までの素材で作れる装備レシピが順次解放され、次の遠征準備へ繋がります。星後領域を進めてもホームの本編完結表示や第15章の結末は維持されます。

開発用の `tools/balance-report.js` は、実際の職業成長、習得スキル、装備重量、章開始時点で入手可能な標準装備、戦闘エンジンを使って探索を反復します。ゲーム本体のセーブデータは読み書きしません。

```powershell
node tools/balance-report.js --runs 100
node tools/balance-report.js --runs 200 --chapter mirror_tide
node tools/balance-report.js --runs 100 --dungeon frost_coast
node tools/balance-report.js --runs 100 --preparation progression
node tools/balance-report.js --runs 100 --chapter mirror_tide --difficulty all
node tools/balance-report.js --runs 100 --json balance-report.json
```

均衡型・物理型・魔法型・回復なしを比較し、勝率、残HP率、平均戦闘ターン、戦闘不能者数、被ダメージ、回復量、状態異常、抵抗、報酬、30ターン撤退率を集計します。本編の極端な低勝率・高勝率、任意高難度の簡単すぎる状態、編成間格差、長期膠着、回復役を外した方が大幅に強くなる編成逆転を警告します。これは数値を自動変更する機能ではなく、調整候補を発見するための検査です。

敗北した試行については、全滅・長期戦・予告大技・後列崩壊・回復不足・命中不足を分類し、最多失敗地点、戦闘不能になりやすい役割と隊列、命中率、大技ダメージと防御率、後列被害、状態異常ダメージを集計します。勝率だけを見て敵を弱体化せず、編成で解決できる問題か基礎数値の問題かを判断できます。JSON出力にも `failureAnalysis` として含まれます。

敗因分析で、予告大技への防御手段が推奨Lv帯に存在しない問題が判明したため、騎士はLv10で「騎士の守勢」、Lv40で「盾撃」を習得する順序へ変更しました。第2章以降に騎士を採用し、技使用率を上げることで予告大技へ実際に反応できます。攻撃だけを選ぶ編成との違いは戦闘ログと大技防御率に現れます。

バランス検証用パーティの装備選択は、単純な能力値だけでなく、その探索地に現れる敵分類と状態異常も参照します。対象分類への特攻と、実際に使われる状態異常への耐性を評価へ加えるため、対策装備を実装しても検証用パーティが無視してしまう状態を避けられます。ゲーム画面の装備選択を自動化するものではありません。

第1～4章には攻略先ごとの `monsterScaling` を設定しています。通常敵とボスのHP・攻撃・防御を別々に調整でき、モンスター図鑑の基礎定義や魔境・神域の共通倍率を汚さずに難易度曲線を変更できます。序盤2地点は操作を覚える区間として余裕を残し、章後半ほど戦闘不能や編成差が現れ、任意攻略は本編より厳しくなる構成です。

## 第5章：鏡潮の海

第4章攻略後に、白霜の海岸、水没した記録院、蒼晶珊瑚の回廊、沈黙の船墓場、鏡潮の宮殿を順番に攻略する第5章を追加しました。章攻略後には、本編進行に不要な任意高難度「深淵鯨の海溝」が解放されます。推奨レベルは本編Lv.28〜36、任意高難度Lv.40です。

新しい水棲・不死・精霊系モンスター、5種類の素材、Tier 6の製作装備3種類、ボス固有装備2種類を追加しました。各探索地には解放時・探索中・攻略後の物語があり、ホームの物語記録と探索ログへ既存章と同じ形式で残ります。第5章達成で第6パーティ、第6章達成で第7パーティの増設権が解放され、コード特典でさらに第8パーティを増設できます。

第5章の氷属性モンスターの一部は、新しい状態異常「凍寒」を付与します。凍寒中は行動速度が30%、回避が35%低下します。付与時の戦闘ログにも効果が表示されるため、行動順や命中の変化を観察しながら編成を試せます。ドワーフと機械人形は凍寒へ少し耐性を持ちます。

第5章の各ボスには異なる攻略上の特徴があります。沈黙の司書は長期戦で毒を重ね、蒼礁の主は凍寒中の相手を追い、凍れる提督は後列を狙いやすく、鏡海女王は凍寒中の相手へ強まる予告大技を使います。通常攻撃は前列ほど狙われやすく、後列狙いは一部の敵だけが持つ特性です。杖だけを装備した冒険者の通常攻撃は魔法攻撃力と魔法防御力を使い、技は物理、呪文は魔法として扱われます。

凍寒への対抗手段として、第5章到達前から用意できる嵐渡りの外套に「凍寒耐性+20%」、第5章クリア後の霜印の祭衣に「凍寒耐性+35%」を追加しました。装備耐性と種族・生まれの耐性は確率合成され、装備変更画面の「特性・装備効果」と耐性表示へ反映されます。また、状態異常を解除できる回復役は、味方のHPが満タンでも状態異常が残っていれば解除行動を選べるようになりました。

## 第6章：止まった砂の都

第5章攻略後に、潮引きの石門、白砂の街道、止まった時計塔、歯車王の工房、砂時計の王宮を順番に巡る第6章を追加しました。章攻略後には、本編進行に不要な任意高難度「忘却巨人の墓」が解放されます。推奨レベルは本編Lv.38〜46、任意高難度Lv.50です。

機械・造物、精霊、巨人など16種類のモンスター、5種類の素材、Tier 7の製作装備3種類、ボス固有装備2種類を追加しました。全モンスターは分類・固有素材・固有装備を持ち、各探索地には解放時、探索中、攻略後の物語があります。章達成で装備強化上限が＋13まで上がり、新しい製作レシピが解放されます。

## パーティ増設

パーティは初期1隊です。第1章クリアで第2パーティ、第2章クリアで第3パーティという順に、章を一つ終えるたび次の増設権を獲得します。権利を得ただけでは自動解放されず、パーティ画面で所持金とギルド印章を支払って増設します。費用は第2隊から順に、10,000G・印章2個、100,000G・4個、500,000G・6個、2,000,000G・8個、8,000,000G・10個、30,000,000G・12個です。第6章達成までに最大7隊の増設権が揃い、コード特典「追加パーティ増設権」を解放すると、第8隊を100,000,000G・印章15個で増設できます。

各隊の編成、探索、直近ログは、パーティ進行マスターの最大数を基準にした配列として保存します。現在の上限は通常進行7隊＋コード特典1隊の合計8隊です。将来は `data/partyProgression.js` に増設条件を追加して `maximum` を変更すれば、初期データ、操作検証、パーティ画面、探索処理が同じ最大数へ追従します。

既存の同じセーブ形式に対して最大数を増やした場合は、不足する未解放枠を空の状態で自動追加します。章進行を巻き戻したり、未増設枠へ編成・探索データを混在させたりできないよう、セーブ読み込み時にも整合性を検証します。旧2隊形式との変換処理は持たず、現在のセーブ形式はバージョン11です。

冒険者を雇用して装備を整え、ダンジョンへ送り出すブラウザ向け放置ハック＆スラッシュゲームです。HTML / CSS / JavaScript と localStorage のみで動作し、サーバー・データベース・ビルド環境は不要です。PC中心のレスポンシブUIで、スマートフォンにも対応しています。

## 定期依頼（デイリーミッション）

冒険者資料室の「依頼掲示板」に、端末日付の0時に更新される日課依頼を追加しました。「ログイン」は毎日固定で、残る2枠は「出撃」「攻略」「施設収穫」「商店購入」「鍛冶製作」から日ごとに抽選されます。各依頼からギルド印章を1個獲得できます。報酬は個別または一括で受け取れ、達成数・受取状況・更新日・その日の抽選結果はセーブデータへ保存します。受取可能な報酬がある間は、資料室と依頼掲示板タブに緑色の件数通知を表示し、観察日記の新着通知とは区別します。

定期依頼の定義は [data/recurringMissions.js](data/recurringMissions.js)、期間更新・抽選・進捗・報酬処理は [js/recurringMissions.js](js/recurringMissions.js) に分離しています。依頼区分ごとに日次／週次、更新時刻、候補プール、抽選数、進捗条件、報酬を定義できます。抽選結果は期間キーから決定するため、同じ期間内に再読み込みしても変化しません。出撃や帰還と同じゲーム操作内で進捗を更新し、保存に失敗した場合は報酬・進捗とも操作前へ戻ります。

週間依頼は毎週月曜0時に更新され、「5回／10回出撃」「3回／7回攻略」の候補から2件を固定抽選します。報酬は所持金とギルド印章で、日課より長い目標を普段の探索で自然に進められます。同じ週は再読み込みしても依頼内容が変わりません。将来さらに定期依頼区分を追加した場合は、既存セーブへ次回同期時に不足区分だけを追加します。

## 素材で強化するギルド施設

採掘場とギルド運営は、章達成による自動成長ではなく、所持素材を投入して強化する施設レベル制です。各施設は「生産量」「保管庫」「作業速度」の3系統をLv.1～5まで独立して強化できます。生産量は1回分の獲得量、保管庫は最大保持時間、作業速度は生産間隔を変化させます。

初期性能は1時間ごと・最大1時間です。保管庫は1・2・4・8・12時間と伸び、作業速度は「1時間÷設備Lv」で、60・30・20・15・12分へ短縮されます。改修時点までに完成していた生産物は旧性能のまま施設内へ確定して保持し、作業途中の1回分だけをリセットします。施設レベルと蓄積物はセーブデータへ保存され、オフライン中も現在の設備性能で進行します。

施設IDや報酬種別は処理側へ直書きしていません。[data/facilities.js](data/facilities.js) の `definitions` と表示順の `order` に施設を追加すると、初期セーブ生成、生産、3系統の強化、画面、操作検証、セーブ検証へ自動的に参加します。通常報酬に加え、「数回の生産ごとに素材を得る」定期報酬を複数定義できます。計算と強化処理は [js/facilities.js](js/facilities.js) に分離しています。

第7章攻略後には「黒樹薬草園」が解放されます。黒樹液から生産を始め、設備を強化すると月光葉・魔女火・聖棘も栽培できます。未解放中は生産時間が進まず、解放を同期した時刻から最初の1時間を数えます。後から施設マスターを追加した場合も既存セーブへ安全な初期状態を補い、ほかの施設の蓄積を変えません。

ギルド施設の見出しには、受け取れる施設数を示す「まとめて受取」ボタンを追加しました。自動収穫にはせず、プレイヤーがギルドへ戻った時に一度の操作で全施設を収穫できます。施設ごとの個別受取も残しています。

## 獲得系スキル

スキル効果に `acquisitionModifier` を追加し、取得金額、取得経験値、装備の上位品質付与率、アイテム獲得率、探索時間を共通形式で補正できるようにしました。金額は倍率と固定値、経験値は本人対象とパーティ対象を使い分けられます。品質・アイテム・探索時間を含むパーティ効果は、同じスキルIDを複数人が持っていても1回だけ適用し、異なるスキル同士は累積します。

## アイテム図鑑の入手元

発見済みアイテムの「入手元を確認」を開くと、商店、鍛冶屋、宝箱に加え、ドロップするダンジョンとモンスターを確認できます。モンスター入手元は「風鳴りの草原・スライム・通常／魔境／神域」のように難易度までまとめ、上位称号が下位ドロップを包含する関係も反映します。同じモンスターが複数のダンジョンに登場する場合は、ダンジョンごとに記載します。

アイテム図鑑では、未発見品を1点ずつ同じ「？？？」カードで並べず、武器種・防具種・素材の各分類につき1枚へまとめて未発見数を表示します。入手済みの品だけが個別カードになり、性能と入手元を確認できます。

商店には毎日4時に更新される日替わり商品が10点並びます。候補になるのは一度でも入手して図鑑へ登録された武器・防具だけです。品質と追加性能を持つ個体として販売し、基礎価格・品質・追加性能・装備スキル数に応じて価格が上がります。同じ日は再読み込みしても品揃えが変わらず、各枠は1回だけ購入できます。入手済みの種類が10種類未満の場合は、同じ装備の異なる性能が複数枠へ並びます。状態はセーブデータの `dailyShop` に保存します。

通常商品とモンスターが落とす汎用品は、[data/shop.js](data/shop.js) の共通カタログを参照します。新規データではTier 1だけが並び、本編の章を完了するたびに次のTierが10種（細剣・剣・太刀・弓・杖・法衣・軽鎧・重鎧・盾・篭手）ずつ入荷します。未解放の商品IDを直接指定して購入することもできません。通常ダンジョンは章番号と同じTier、魔境は1段階先、神域は2段階先の汎用品を落とすため、探索先の進行に伴って商店系ドロップも更新されます。汎用品の固定スキルは装備種ごとに定まり、Tier 3とTier 7で1つずつ増えて最大3個になります。製作品・モンスター固有品・ボス固有品はこのカタログへ混在しません。入荷が増えた後も各装備種では最新2Tierだけを先に表示し、それ以前の商品は「過去の品」から展開できます。

分類別の通常装備抽選も実際の候補を計算して表示します。通常装備抽選には商店購入可能な装備だけを含め、製作専用・ドロップ専用・ボス固有装備は混在させません。固有品は対応モンスターの固有入手元として区別します。

## 種類別アイテム図鑑

アイテム図鑑は武器・防具・素材の一列表示ではなく、武器は剣・細剣・刀・弓・杖、防具は布装備・革装備・重装備・盾・小手、残りは素材として折りたたみ分類します。分類ごとに発見数／登録数を表示し、分類内ではTierと名前の順に並べます。装備や素材が増えても、必要な種類だけを開いて確認できます。

## ダンジョン別モンスター図鑑

冒険者資料室のモンスター図鑑をダンジョン別の折りたたみ一覧へ変更しました。各モンスターには「通常・魔境・神域」の記録欄があり、難易度ごとの遭遇数、討伐数、実際に確認した素材・固有装備・ボス固有品を表示します。未遭遇の難易度と未確認のドロップは伏せたまま残ります。

分類に応じて抽選される商店購入可能な通常武器・防具は図鑑のドロップ欄へ記載しません。モンスター固有素材、商店では買えない固有装備、称号モンスター固有品だけを調査対象にしています。図鑑セーブは難易度ごとのドロップと目撃した固有技を保持するバージョン5です。

## ダンジョン難易度

各ダンジョンは「通常 → 魔境 → 神域」の順に攻略します。通常版の攻略で同じダンジョンの魔境、魔境の攻略で神域が解放されます。画面上の難易度名は攻略先と直接対応し、「魔境の風鳴りの草原」「神域の風鳴りの草原」のように表示します。通常攻略だけが本編進行条件になり、魔境・神域はダンジョンごとのやり込み記録として保存されます。

魔境は基本探索時間1.5倍、神域は2.5倍になり、敵能力・報酬・推奨レベルも共通難易度マスターから補正します。難易度倍率とプレイヤーが選ぶ1～6倍探索は乗算されます。設定は [data/dungeonDifficulties.js](data/dungeonDifficulties.js)、解放・変換処理は [js/dungeonDifficulty.js](js/dungeonDifficulty.js) に分離しています。

各ダンジョンの難易度別初回踏破報酬として、魔境ではギルド印章1個、神域では2個を獲得します。同じダンジョン・同じ難易度でもらえるのは一度だけです。攻略先には未獲得の報酬を表示し、帰還結果では通常の周回報酬と分けて通知します。報酬定義は難易度マスターに置き、今後は所持金や別素材も追加できます。

称号モンスターは `モンスターID × 難易度ID` の個別プロファイルを持ちます。神域は神域・魔境・通常の固有ドロップテーブルをすべて独立抽選し、魔境は魔境・通常を抽選します。スライムには魔境・神域専用素材と防具を実装済みです。

称号ごとの固有技は [data/monsterSkills.js](data/monsterSkills.js) にまとめ、付与関係は `GameData.relations.monsterDifficultySkillGrants` に分離しています。魔境スライムの「粘液波」、神域スライムの「神域分裂撃」、黒月の祭司の「記憶封印」「黒月典礼」を実装し、神域個体は魔境の技も継承します。固有技は設定したターン周期で通常行動の代わりに発動し、対象・物理／魔法・属性・状態異常をデータだけで追加できます。戦闘ログには技名と周期を残します。

第1～10章の本編終盤ボスには、魔境固有技と神域専用の第二固有技を1つずつ設定しています。月牙の遠吠え、地脈の過負荷、星環による後列攻撃、炎・凍寒・毒・麻痺を伴う全体技など、章と難易度の戦闘テーマに沿って挙動が変わります。神域個体は魔境技も引き継ぎ、同じターンに複数の技が発動可能になった場合は使用回数の少ない技を優先するため、片方だけが使われ続けることはありません。

モンスター図鑑の固有技は討伐だけでは解放されず、戦闘中に実際の発動を目撃した技だけが難易度別に記録されます。敗北・撤退しても観察内容は失われず、未観測の技は名前を伏せたまま残るため、強敵へ挑んで情報を持ち帰ること自体に意味があります。通常個体には称号技を適用しません。

## モンスター固有ドロップ

全モンスターに、低確率の固定素材と固定装備を設定しました。固定装備は商店では購入できない製作系またはドロップ専用品で、分類別の通常装備抽選やボス固有品とは別に判定します。通常敵は素材8%・装備3%、ボスは素材12%・装備6%が基準です。スライムは「ねばねばした液体」10%、「ぼろぼろの布切れ」4%、専用防具「粘液染みの外套」3%を持ちます。

設定は [data/monsterDrops.js](data/monsterDrops.js) に集約し、各モンスターから何が落ちるかを一覧で編集できます。戦闘ログでは通常素材と区別して「固有素材」「固有装備」と表示し、実際に確認した内容だけがモンスター図鑑へ登録されます。1～6倍探索では既存報酬と同じ効率補正を適用します。

## モンスター分類ドロップと種族特攻

通常装備はダンジョン一括抽選ではなく、倒したモンスター1体ごとに抽選します。探索先の推奨レベルから通常装備のTierを決め、獣なら弓・刀・革・小手、機械・造物なら剣・杖・重装・盾・小手というように、モンスター分類に合う装備種だけを候補にします。素材とボス固有装備は従来どおりモンスター個別テーブルです。長時間探索では装備抽選回数も増えますが、抽選率を補正し、同じ時間なら短時間探索を繰り返す方が有利です。

冒険者種族とモンスターは、人型・獣・竜・不死・機械／造物・精霊などの共通分類IDを参照します。竜人のような複合分類にも対応しています。装備スキルとして獣特攻1.10倍、造物特攻1.15倍、竜特攻1.10倍、不死特攻1.20倍を追加し、「竜災の備え」と「天上の加護」にも特攻効果を追加しました。装備由来と種族・生まれ由来は乗算され、発動時は戦闘ログに対象分類と最終倍率を表示します。分類・ドロップ傾向は [data/creatureFamilies.js](data/creatureFamilies.js)、抽選処理は [js/monsterLoot.js](js/monsterLoot.js) に分離しています。

## 固定装備スキルと超レア称号

装備スキルのランダム抽選を廃止し、武器・防具ごとに1～5個の固有スキルを定義しました。同じ鉄の剣なら品質や追加性能が異なっても固有スキルは共通です。固有スキルの付与関係は [data/itemSkills.js](data/itemSkills.js) の `GameData.relations.itemSkillGrants`、効果本体は [data/equipmentSkills.js](data/equipmentSkills.js) に分離しています。装備テンプレート本体へ `skillIds` は混在させません。

強化＋3と＋6では、剣・細剣・刀・弓・杖・布・革・重装・盾・小手ごとに固定された強化スキルを習得します。次の強化でスキルを得る場合は強化画面と完了ログへ明示され、個体セーブには強化段階だけを保存します。

探索ドロップには0.1%で、通常の品質称号とは別枠の「超レア称号」が付きます。超レア品は重量を除く装備パラメータがさらに2倍になり、称号ごとに固有スキルを1つ得ます。取得時に自動ロックされ、自動売却へ登録できません。称号設定は [data/ultraRareTitles.js](data/ultraRareTitles.js) に集約しています。現在のセーブ形式はバージョン11で、旧式の個体別ランダム装備スキルは移行しません。

## 種族・職業・生まれの固有スキル

職業・種族・生まれは、それぞれレベルに関係なく有効な初期スキルと、成長によって習得するスキルを持ちます。

- 生まれ：初期スキル4種、Lv.1、Lv.20、Lv.60、Lv.100
- 種族：初期スキル4種、Lv.1、Lv.30、Lv.60、Lv.100
- 職業：初期スキル4種、Lv.10、Lv.40、Lv.70、Lv.100

職業・種族・生まれにはそれぞれ4種の初期パッシブを持たせています。効果は装備スキルに近い小倍率ですが別枠で乗算され、両方を重ねられます。レベル習得枠は技・呪文・回復・特性を成長段階に応じて解放します。習得関係は [data/skillGrants.js](data/skillGrants.js)、初期・発展特性は [data/progressionSkills.js](data/progressionSkills.js) に分離しています。

固有特性は物理／魔法の与ダメージ、物理／魔法の被ダメージ、命中率、回避率、会心率、戦闘中の回復量へ実際に反映されます。倍率は別名スキル同士なら乗算し、命中・回避・会心のpt補正は加算します。出撃時に習得済みスキルIDを固定するため、探索中のレベルアップで出撃済み戦闘の条件は変化しません。初期習得とレベル習得はマスターデータ上でも別フラグで区別します。

設計は「生まれ＝小さな初期補助」「職業＝戦闘役割の中核」「種族＝育成後に加わる身体・魔力特性」と分担しています。参照作品の名称・数値は使用せず、このゲームの既存能力と戦闘式に合わせた独自データです。

## 装備変更画面の能力・スキル一覧

装備変更画面では、最大HP、物理／魔法の攻撃・防御・回復、命中、回避、速度、攻撃回数、会心、各種威力を「冒険者 ＋ 装備 ＝ 合計」の形式で一覧表示します。装備欄は単純な基礎値ではなく、その冒険者の装備適性、品質、追加性能、強化段階、装備スキルの倍率・能力変換、固有効果まで反映した最終的な寄与です。

同じ画面では、戦闘中に選択して使う「技」と「呪文」を別々の欄に表示します。職業・種族・生まれ・前職由来のパッシブ／リアクション、装備スキル、ボス固有効果は「特性・装備効果」へまとめ、名前・説明・習得元または装備元を確認できます。属性被害倍率と状態異常耐性も表示します。能力欄は最初から開き、不要なときはキャラクター行を押して折りたためます。

技・呪文・特性・装備効果は、閉じた状態では分類と名前だけを1行で表示します。行をタップすると説明と習得元／装備元がその行の下へ展開され、もう一度タップすると閉じます。

## パーティ編成の能力表示

メンバー編成と所属冒険者の一覧は、編成判断で頻繁に使う職業・種族・レベル・HP・装備重量に情報を絞りました。装備重量は現在値／最大値で表示し、上限の90%以上では警告色になります。所属冒険者は名前・職業に加えて種族でも検索できます。攻撃や防御などの詳細能力は一覧に重複表示せず、キャラクターの装備画面で確認します。

## 装備種類の表示

全武器・防具は、共通マスターで定義された武器種または防具種を必須とします。武器は剣・細剣・刀・弓・杖、防具は布装備・革装備・重装備・盾・小手に分類されます。所持品では「剣 · 近接 · 品質：標準」、装備変更画面では「剣 · 品質：標準」のように、装備種類・射程・品質を混同しない表記にしています。マスターデータ検証では、種類未設定、存在しない種類、武器／防具カテゴリの不一致、武器射程の欠落をエラーにします。

## 装備の売却と自動売却

所持品では装備個体ごとの売却に加え、性能が同じグループの未装備・ロックなし装備をまとめて売却できます。確認画面に対象数と合計金額を表示し、装備中またはロック中の個体は常に残します。

探索ドロップの自動売却はフィルター条件ではなく、所持品にある装備グループを直接指定します。装備グループを開いて「同じ性能を自動売却」を押すと、装備テンプレート、品質、強化段階、ランダム追加性能、超レア称号がすべて一致する装備だけが対象になります。登録数に上限はありません。自動売却額と対象装備は探索結果にも記録されます。

誤売却を避けるため、自動売却の対象は探索で新しく得た未強化の通常装備だけです。商店購入品、鍛冶製作品、ボス固有装備、超レア称号付き装備、すでに所持している装備、装備中・ロック中の装備には適用しません。設定はセーブデータの `autoSell` に保存されます。`node tests/auto-sell.test.js` でルール判定、安全対象、探索報酬、まとめ売却、セーブ検証を確認できます。

## 同一装備のまとめ表示

所持品とキャラクターの装備候補では、テンプレート、品質、強化段階、ランダム追加性能、超レア称号がすべて同じ装備を1行へまとめ、`×所持数`で表示します。いずれかが異なる装備は別グループになるため、個体差は失われません。

所持品のグループを開くと、保存上の個体ID、装備者、ロック状態を確認し、個体ごとにロック・売却・分解できます。装備候補から「装備」を押すと、そのグループの未装備個体を1個だけ装着し、残数が更新されます。セーブデータでは従来どおり全装備を個体管理し、表示時だけまとめているため、装備・売却・分解・ランダム性能の仕組みは維持されます。

## 観察して組み立てる攻略情報

攻略先の成功率と、編成の正解を直接示す対策リストは表示しません。出撃前に読めるのは短い依頼文と先行隊の噂だけです。未遭遇の敵は名前も伏せ、遭遇後に現地記録が増えていきます。敗北報告も改善案ではなく、撤退した戦闘、30ターン終了時の敵残存、大技の被害、後列への被害、総被ダメージと回復量という観測事実を残します。

戦闘ログでは攻撃回数と命中数、回避、属性の弱点・耐性、状態異常の付与・抵抗、大技の予告・発動ターン・再発動周期を確認できます。モンスター図鑑は遭遇・討伐・攻撃の試行による3段階調査です。実際に確認した弱点、耐性、攻撃属性、状態異常、後列狙い、行動回数、周期、ドロップだけを蓄積し、十分な討伐と検証を重ねた段階で基礎能力値が開示されます。

## 冒険者の雇用費

募集時には募集専用素材「ギルド印章」、応募者の雇用時には所持金を消費します。雇用費は基本料金に職業・種族・初期能力の評価額を加え、10G単位に切り上げて決定します。HP・攻撃・防御の初期値が高い個体や、物語の後半で解放される希少な職業・種族ほど高額になります。最初の3人には新設ギルド支援として250G、150G、50Gを順番に差し引き、初期パーティを作るまでの負担だけを抑えます。

募集演出、応募者一覧、詳細確認、クイック雇用のすべてで雇用費を表示します。確認画面では料金内訳、新設ギルド支援、現在の所持金、雇用後の残金を確認でき、所持金不足の場合は雇用できません。料金表と能力評価係数は `data/recruitment.js` の `pricing` に集約しています。応募者やセーブデータへ価格を複製せず、現在の雇用人数と応募者データから金額を算出します。

所持金の差し引き、冒険者の追加、残りの応募者の退出、保存はひとつの操作として処理されます。保存に失敗した場合は全変更が取り消されます。`node tests/recruitment.test.js` で職業・種族・初期能力による価格差、所持金不足、二重操作、保存失敗時の復元を検証します。

## ギルド印章と募集費用

指定なしの募集は印章1個を消費し、職業・種族・生まれ・得意分野の希望を1項目指定するごとに必要な印章が1個増えます。最大4項目指定時は印章5個です。応募人数は指定数に応じて2〜4人、3〜5人、4〜5人へ増えます。条件を詳しくするほど各地の支部へ多くの募集状を送るという位置付けで、応募者の完全一致は保証しません。

募集フォームでは、希望した職業・種族・生まれが通った場合に得られる初期スキルとレベル習得スキルを、募集前に出自別で確認できます。各スキル名を開くと効果説明を表示します。得意分野を指定した場合は初期能力への影響も併記します。

新規データは印章4個を所持して開始します。初期状態のギルド運営では4回の生産、すなわち作業速度未強化なら累計4時間で印章1個を作ります。初期保管庫は1時間分のため、受け取りながら生産回数を進めます。生産量・保管庫・作業速度を素材で強化すると、印章の生産周期や最大保持量も向上します。ギルド依頼と章クリア報酬からも入手できます。

募集を確定した時点で印章を消費し、応募者を全員見送っても返却されません。フォームでは条件変更に合わせて必要数、所持数、募集後残数、応募予定人数を即時更新します。消費と応募者生成は同じ保存処理で行い、保存失敗時は両方を取り消します。設定値は `data/recruitment.js` の `postingCost` に集約し、所持数は既存の素材インベントリで管理します。

## 第4章：灰冠の大地

第3章攻略後に、5つの本編ダンジョンを順番に進む第4章を追加しました。推奨Lv21の「星降りの峠道」から始まり、「玻璃樹の迷い森」「熾火の旧鉱山」「灰壁の王城塞」を経て、推奨Lv27の「灰冠の玉座」へ進みます。各ダンジョン攻略後の出来事は、章の途中でもホームの「攻略の記録」から読み返せます。

章クリア後には、本編に影響しない推奨Lv30の任意高難度「古灰竜の火口」が解放されます。灰冠王と古灰竜には予告付き全体攻撃があり、氷属性、火傷解除、防御、全体回復を揃える攻略を想定しています。灰冠王から固有防具「灰冠王の炉鎧」、古灰竜から固有武器「古竜灰の大剣」が低確率でドロップします。

新素材は天玻璃・灰樹の芯材・熾火鉱・灰冠の炉心・古竜の灰鱗の5種類です。章クリア後、Tier5の「暁玻璃の細剣」「熾火の城盾」「灰樹織りの外套」を製作できます。第4章の装備・敵・探索先・物語・レシピは [data/chapters/chapter4.js](data/chapters/chapter4.js) に章単位でまとめています。`node tests/chapter-four.test.js` で5つの段階解放、任意攻略、物語、素材、製作、ボス装備、セーブ検証、推奨レベル帯の暫定戦闘標本を確認します。

## 章・ダンジョン進行の基盤

15章までの本編と16～20章のやり込み追加を見据え、章進行をデータ駆動へ整理しました。ダンジョンは `chapterId`、章内順 `orderInChapter`、本編必須かを示す `requiredForStory`、汎用の `unlockRequirements` を持ちます。章の達成判定は、その章に属する本編必須ダンジョンを自動収集して行うため、1章に5個の攻略先を追加しても判定コードの書き換えは不要です。

解放条件は章達成・ダンジョン攻略・冒険者数・初出発・アイテム所持を共通形式で扱えます。章本文は `storyScenes` へ分離し、章は開始・クリア物語のIDだけを参照します。任意高難度ダンジョンは `requiredForStory: false` と `optionalStoryId` を設定することで、本編を止めず、攻略後だけ追加物語を「これまでのストーリー」へ登録できます。現在の雷鳴の天文塔を第3章の最初の任意高難度枠へ移行しました。

ホームでは現在章の設計レベル帯、本編／任意の攻略路と達成状況を確認できます。パーティの攻略先一覧でも本編と任意高難度を明示します。保存データは引き続き達成章IDと攻略済みダンジョンIDだけを保持し、章・物語本文・解放条件などのマスターデータを混在させません。`node tests/chapter-progression.test.js` で複数の本編ダンジョン、段階解放、任意攻略、追加物語、章報酬の一度限り付与を検証します。

## 状態異常と属性

毒・火傷・麻痺を実装しました。毒はターン開始時に継続ダメージ、火傷は継続ダメージと物理攻撃力10%低下、麻痺は次のターンを行動不能にします。同じ状態異常は重複せず、残り時間と効果量の強い方へ更新されます。戦闘ログには付与・抵抗・継続ダメージ・行動不能・解除・自然回復を専用の行として表示します。

炎・氷・雷・自然・闇・魔力・無属性を共通マスターとして追加しました。スライムの炎弱点、雷属性の天文塔モンスターが持つ氷弱点など、敵ごとに弱点・耐性を設定できます。種族・生まれにも属性倍率と状態耐性を設定でき、機巧人の毒無効、竜人の炎耐性などを戦闘開始時のスナップショットへ保存します。

スキル効果へ `applyStatus` と `cleanse` を追加し、ダメージ効果は任意の `element` を持てます。火球・茨の槍・ルーン火花・竜の息吹等に属性と状態異常を設定し、盗賊Lv6「毒刃」、魔術師Lv6「吹雪」、僧侶Lv6「浄化の光」を追加しました。モンスター図鑑では、戦闘中に実際に確認できた属性攻撃、弱点・耐性、状態異常を段階的に確認できます。

処理は `data/combatEffects.js` と `js/statusCombat.js` に分離しています。`node tests/status-elements.test.js` で効果形式、持続時間、継続ダメージ、攻撃低下、行動不能、解除、種族耐性、属性弱点、戦闘ログを検証します。

## 起動方法

1. このフォルダーの `index.html` をブラウザで開きます。
2. 冒険者メニューから募集を出し、応募者を1人選んで雇用します。
3. 冒険者に武器・防具を装備し、パーティを編成します。
4. ダンジョンと探索時間倍率を選んで出撃します。
5. 帰還報酬で装備の製作・強化を進め、物語の依頼を達成します。

Node.jsはゲームの起動に不要です。同じブラウザ・同じ保存領域で遊んでください。ファイル直接起動の保存領域はブラウザに依存します。保存できない場合はブラウザの設定を確認してください。別ブラウザ・別端末への移動にはセーブJSONを使います。

同じWi-Fiのスマートフォンから確認するときは、PCで `node tools/dev-server.js 8091` を実行します。起動後にPC用URLとスマートフォン用URLが表示されるため、スマートフォンでは「スマートフォン」と書かれたURLを開きます。Pythonを利用する場合は `python serve.py` でも起動できます。どちらの開発用サーバーもキャッシュを無効化するため、ページ更新で最新のHTML・CSS・JavaScriptが反映されます。

PC上でスマートフォン用レイアウトを並べて確認する場合は、サーバー起動後に `/tools/mobile-preview.html` を開きます。390px幅と430px幅を同時表示し、下部タブ、画像選択、募集結果、パーティ編成などのレスポンシブ表示を比較できます。このページは開発確認専用で、ゲーム本体やセーブ形式には影響しません。

## 探索・戦闘のルール

探索時間は1〜6倍で選択します。時間を増やすと道中の戦闘回数が増え、ボスは1回のみです。成功時のお金・経験値の報酬範囲は時間倍率の平方根に比例します。素材は品目ごとに期待量を抑え、短時間出撃を繰り返す方が時間当たりの報酬効率は高くなります。通常装備・ボス装備の抽選は出撃1回分、章報酬と攻略依頼は時間倍率で増えません。自動周回はありません。

出撃時の時刻・終了時刻・時間倍率・乱数シード・参加者の能力／習得スキル／行動率を保存します。ブラウザを閉じても終了時刻から帰還を判定し、報酬は一度だけ処理します。探索中の装備や行動率の変更は次回出撃から反映します。

探索中の「探索の記録」は、保存済みの出撃スナップショットと乱数シードから同じ探索内容を再現し、実時間の進行に合わせて出発・遭遇・戦闘行動・勝敗を順に開示します。戦闘ログは遭遇行の内側にあり、行を開閉して確認します。この途中表示は状態や報酬を変更せず、報酬の確定と付与は従来どおり帰還処理で一度だけ行います。再読み込み後も同じ記録が復元されるため、セーブ形式の変更はありません。

- 行動順は速度を基準に小さな乱数差を加えて決定します。
- 攻撃回数は速度と装備性能から算出し、1〜8回です。通常物理攻撃は攻撃回数ぶん連続攻撃し、対象を倒した後は生存中の敵へ攻撃を続けます。物理技は技固有のヒット数、呪文は原則1回です。
- 連続攻撃の命中補正は1撃目100%、2撃目60%、3撃目以降は直前の90%。威力補正は1〜2撃目100%、3撃目以降は直前の90%です。各攻撃で命中・防御・隊列・会心を個別判定します。
- 戦闘ログは連続攻撃を1行にまとめて「攻撃回数・命中数・合計ダメージ・会心数」を表示し、帰還報告には冒険者ごとの物理命中数／試行数を記録します。
- 近接武器は後方ほど、遠距離武器は前方ほど攻撃が弱くなります。4〜6人編成では実際の人数に合わせて隊列補正を補間します。
- 敵も遭遇グループ内で前・中・後列を組み、近接／遠距離に応じた隊列補正を受けます。遭遇時の戦闘ログに敵の配置と補正を記録します。
- 通常攻撃は物理攻撃です。杖は低い物理性能と独立した魔法性能を持ち、魔法・回復に向きます。
- 命中率は攻撃側の命中−対象の回避を10〜99%に制限して判定。ボスの全体大技は必中です。
- 物理は物理攻撃と防御、魔法は魔法攻撃と魔法防御を使用。防御による減算、威力、隊列、乱数、会心、敵弱点、保護等を適用します。会心の基本威力は1.65倍です。
- 回復は魔法回復力と回復補正を使用します。死亡による冒険者の永久消失はありません。
- パッシブは条件を満たす間常時有効です。同じ号令・後方守護は重複せず、習得者の戦闘不能で無効になります。
- 技・呪文・回復にはスキルごとの再使用ターンがあります。軽い技や単体回復は短く、強力な全体技は長めです。使用したスキルが待機中でも同系統の別スキルは選択でき、すべての待機は戦闘ごとにリセットします。MPはありません。
- リアクションは条件成立時に即座に発動し、各スキルは1戦闘1回。致死ダメージ後の回復はありません。
- 各冒険者は攻撃・技・呪文・回復の使用率をそれぞれ0〜100%で設定します。合計値の制限はなく、回復、呪文、技、通常攻撃の順に使用可能な行動を個別判定します。すべて外れた場合は防御し、次に受けるダメージを半減します。単体攻撃の対象は自動選択され、前列ほど狙われやすく、後列狙いやすさを上げる職業スキルで分布が変わります。
- 戦闘は最大30ターンで撤退し、連戦ではHPを引き継ぎます。戦闘バランスの最終調整は未実施です。

攻撃回数の設計は『冒険者ギルド物語2』攻略情報にある、敏捷が攻撃回数・命中・回避・行動順へ影響する関係と、多段攻撃の後半ほど命中・威力が減衰する考え方を参考にしています。数値と上限は本作の戦闘時間・既存能力に合わせて調整しています。

## v0.30の整理内容とセーブの扱い

旧形式1〜4の自動移行、保存項目の後付け補完、物語の引き継ぎ専用解放、直接作成API、移行専用テストを削除しました。全探索に現行戦闘ルールを適用し、加入は募集・雇用、解放は章達成に統一しています。

現在のセーブ形式はバージョン11です。装備は順序付きの個体ID配列として保存します。旧形式は利用できず、古い形式・項目不足・不正な内容は原則として自動変換しません。起動時はエラーを表示して自動保存を停止し、元の保存データを保護します。必要なら画面から元データを書き出して保管し、確認付きの「セーブデータ初期化」で新規開始してください。新しい定期依頼区分のような、同じ形式内の追加マスターだけは不足分を安全に生成します。

## マスターデータの構造

ゲーム定義は `window.GameData`、プレイヤーの進行状況は `window.GameState.data` に分離しています。セーブには職業・種族・装備テンプレート等を複製せず、安定したIDと装備個体固有の値だけを保存します。各マスターではオブジェクトのキーと `id` を一致させ、`name` は画面に表示する名称として扱います。

- `masterSchema.js` はマスター構造の版番号と `config`・`relations`・`derived` の名前空間、および追加コンテンツ用の登録APIを初期化します。
- `GameData.registry.entities(tableName, entries)` は章・クリア後コンテンツが追加する装備・敵・探索地・物語を一括検証し、ID不一致や既存IDの上書きを登録前に拒否します。
- `GameData.registry.entityList(tableName, entries)` は章・レシピ・依頼のような順序付きマスターを一括登録し、既存リスト内と同一バッチ内のID重複を反映前に拒否します。
- `GameData.registry.relations(tableName, entries)` は装備スキルや敵ドロップなどの関係データを一括検証し、既存の関係IDを登録前に拒否します。
- `GameData.registry.relationList(tableName, entries)` は物語イベントのような順序付き関係リストを一括登録し、既存リスト内と同一バッチ内のID重複を反映前に拒否します。
- `GameData.config` は人数上限など、エンティティではないシステム設定を保持します。
- `GameData.relations` は人物とスキル、人物と成長段階、物語条件と効果、探索地と編成制限など、複数マスターのIDを結ぶ関係だけを保持します。
- `GameData.derived` は省略値の補完など、元のマスターを変更せず共通ルールから生成した参照用データを保持します。セーブ対象にはしません。
- 装備と固定スキルの関係は `GameData.relations.itemSkillGrants` に置き、装備本体の能力値から分離します。
- モンスターと通常素材の関係は `GameData.relations.monsterMaterialDrops` に置き、`MonsterLoot.materialDrops()` を唯一の参照窓口にします。
- モンスターと固有素材・固有装備の関係は `GameData.relations.monsterSignatureDrops` に置き、敵の戦闘能力から分離します。
- モンスター／冒険者種族と生物分類の関係は `GameData.relations.monsterFamilies`／`adventurerFamilies` に置き、特攻・ドロップ傾向の参照は `MonsterLoot` に集約します。
- 探索地と冒頭・発見シーンの関係は `GameData.relations.dungeonStoryLinks` に置き、探索ルールから物語参照を分離します。
- 章・探索地・シーンのエンティティ本体には、別機能が後から追加する効果や制限を混在させません。

- `skills.js` は全スキルの表示情報、発動方法、対象、効果配列だけを定義します。
- `skillGrants.js` は職業・種族・生まれと、習得スキル／習得レベルの関係だけを定義します。
- `affinities.js` は全装備種別と、職業・種族・生まれの装備適性を同一形式で定義します。
- `jobs.js` と `origins.js` は能力補正と表示情報を持ち、スキルや装備適性を内包しません。
- スキル効果はすべて `activation`、`targeting`、`effects[]` の共通形式です。戦闘側は効果種別を解釈し、個別スキルIDによる分岐を持ちません。
- `combatEffects.js` は属性・状態異常の共通定義だけを保持します。種族・生まれ・敵固有の耐性や弱点は、それぞれの本体定義に明記します。
- 装備が省略した魔法能力は `GameData.derived.itemCombatStats`、敵が省略した魔法能力・命中・回避は `GameData.derived.monsterCombatStats` へ展開し、戦闘能力本体へ後から混在させません。

`node tests/master-data.test.js` でIDと表示名、参照先、統一スキル形式、習得表、装備適性、レシピ・敵・探索地の参照、マスターとセーブの分離を検証します。`node tests/master-registry.test.js` では追加マスターの正常登録、ID不一致、重複、および不正な一括登録の原子性を検証します。

現行仕様で必要な入力検証、ID・装備参照・重量・章上限の検証、保存失敗時の取り消し、任意項目の既定値は残しています。保存形式と操作プロトコルの版番号は検証用です。保存場所の識別キーは不用意なデータ消失を避けるため変更していません。

Web制作スキルに沿って既存のギルドUIを維持し、引き継ぎ専用表示を除去、読み込みエラーの案内を追加しました。localStorageやユーザーの保存ファイルをこの作業で削除することはありません。

## 検証方法

```

  if ($LASTEXITCODE -ne 0) { throw "Test failed: $($_.Name)" }

```

テストは装備・戦闘・募集・章進行・放置生産・保存検証・保存失敗・オフライン帰還等を確認します。標本戦闘の勝率は固定条件の回帰確認で、最終推奨レベルや実際の編成の勝率保証ではありません。ブラウザでの実操作・見た目の確認は未実施です。

## 拡張ポイント

マスタは `data/`、ゲーム処理は `js/`、表示は `js/ui/` に分離しています。`ui.js` は画面遷移と入力イベントを担当し、パーティ・探索、商店・鍛冶屋、募集・雇用、装備変更の表示を各Viewモジュールが担当します。装備は個体IDを参照し、品質・追加性能・強化・固有效果を分けて保持します。スキルの分類と効果種別も独立しているため、新しい効果や習得条件を追加できます。

画面の変更操作は `GameClient.execute(type, payload)` を通します。内部コマンドは検証と保存をまとめ、状態コピーを返します。通信窓口・保存先・時計・乱数は差し替え可能ですが、サーバー通信・認証・クラウド同期・不正防止はまだ実装していません。各ゲームモジュールの公開関数は内部コマンドが利用する現行APIです。

新しい敵・装備・素材・章・募集項目・依頼等はマスタを中心に追加します。新しい効果や状態項目を導入した場合は、処理・表示・セーブ検証・テストも合わせて更新してください。状態異常、より多様な敵やスキル、実績等は今後の拡張対象です。

## 詳細画面と攻略先選択

パーティ詳細は「戻る・現在の画面名・パーティ状態」を共通ヘッダーにまとめています。パーティ一覧へ戻ると、開く前のスクロール位置へ復帰します。

攻略先は章タブで切り替え、選択した章の本編5区画だけを一覧表示します。章タブと章見出しには攻略数を表示し、現在章を最初に開き、次に進める本編区画を強調します。攻略済みの過去章と未解放の将来章も確認でき、任意高難度は本編と分けて章の末尾に表示します。

各攻略先では、推奨レベル・基本時間・戦闘数・探索倍率・選択操作を常時表示します。成功率は表示しません。依頼、噂、確認済みの敵、発見物、報酬ルールは必要な攻略先だけ展開できます。選択中の攻略先と出撃ボタンはスクロール中も上部へ固定し、スマートフォンでは章タブを横へ短く切り替えられるため、全章を縦に読み飛ばす必要がありません。表示章と探索倍率はパーティごとの一時的な画面状態で、セーブデータ形式には追加していません。

`node tests/party-workflow.test.js` で章切り替え、章内表示、攻略先選択、パーティ別の探索倍率、一覧からの出撃を既存の編成・探索導線とまとめて確認します。

冒険者画面も一覧と詳細を分離しています。一覧は名前・職業・レベル・主要能力だけを短い行で表示し、選択すると能力、スキル、出自、装備をまとめた詳細画面へ進みます。詳細上部から装備変更と転職確認を直接開けます。一覧へ戻ると検索・並べ替え・ページ・スクロール位置を維持します。

所持品は保管・検索・ロック・売却・分解・自動売却の管理に役割を絞っています。冒険者との能力比較と所持品からの直接装備は表示せず、装備変更と能力差の確認はパーティ／冒険者側の専用装備画面で行います。

所属冒険者は名前／職業検索・職業絞り込み・レベル／名前／加入順の並べ替えと20人単位のページ切替、所持装備は既存の絞り込み・並べ替えに加えて24点単位のページ切替に対応します。装備変更画面も24点単位のまま、候補を短い行で比較して選択した装備だけ詳細を開く構成です。スマートフォンでは主要情報を絞って一行の高さを抑え、操作ボタンは44px以上を維持します。

「冒険者ギルド物語2」の公開[画面説明](https://wikiwiki.jp/guildmono2/%E7%94%BB%E9%9D%A2%E8%AA%AC%E6%98%8E)にある、キャラクター装備を一覧から変更する導線とカテゴリ選択、および公開[Tips](https://wikiwiki.jp/guildmono2/Tips)にある検索・絞り込みを使った大量アイテム整理の考え方を参考にしています。画面や素材の複製は行っていません。

`node tests/compact-ledgers.test.js` で冒険者20人／装備24点のページ分割、詳細の折りたたみ構造、商店・鍛冶屋・強化のコンパクト表示を検証します。保存データ形式とゲームルールは変更していないため、初期化は不要です。実ブラウザでの見た目・操作確認は未実施です。

装備強化も、テンプレート・品質・追加性能・超レア称号・現在の強化段階が同じ品を1行へまとめます。数量と強化可能数を一覧で確認し、行を開いて装備者や探索中の制限を確かめてから、強化する個体だけを選択できます。ページ数は個体数ではなく装備グループ数で計算するため、同じドロップ品が大量に増えても一覧が必要以上に長くなりません。

## 装備枠の統合

武器・防具を共通の装備一覧へ追加します。武器だけ、防具だけ、同じ種類の別個体も複数装備でき、個数制限はありません。既存の合計重量上限は維持し、全装備の能力・適性・品質・追加性能・強化を加算します。装備可否に使うのは画面に表示される重量の合計だけです。「装備を追加する」で追加後の能力差・合計重量を確認し、一覧の「外す」で個体を指定して解除します。装備中の武器すべてから近接・遠距離を判定します。両方を持つ場合は双方の隊列補正を乗算します（3人編成では前衛62%、中衛69.7%、後衛62%）。同種の武器が複数でも補正は種類ごとに1回で、装備順序に依存しません。武器なしは近接です。ボス固有效果の発動対象はテンプレート単位で重複をまとめ、回復倍率など能力値の補正は各個体に適用します。

編成プリセット・探索時の能力スナップショット・セーブの書き出し／読み込みも新形式に対応しています。旧データは自動移行・自動削除しません。必要なデータを書き出して保管した後、確認付きの初期化で新規開始してください。

`node tests/unlimited-equipment.test.js` で同種複数装備、能力合算、重量、個体解除、重複・所有者保護、隊列判定、プリセット、保存を検証できます。既存UIとレスポンシブ構成は維持しています。

## パーティ・冒険の操作改善

「パーティ」で隊を選び、次の順で操作します。

1. **編成**：出撃メンバーと隊列を先に確認。仲間一覧から追加・解除し、↑↓で隊列を変更します。編成済みメンバーの詳細を開いて装備と4種類の行動率を設定します。装備の追加と個体ごとの解除もこの画面で操作できます。未編成者の設定は表示せず、人数上限・別パーティ所属・探索中の理由を明示します。プリセットは折りたたみ内にあります。
2. **出撃先指定**：選択中の隊とメンバーを確認し、ダンジョンと1〜6倍の探索時間を選びます。「編成・装備を見直す」で戻れます。折りたたみ内には短い依頼と噂、実際に確認した敵の記録だけを表示し、成功率や具体的な推奨編成は示しません。
3. **探索状況／探索結果**：探索中は経過に応じて増える探索記録を表示し、遭遇行を開くとその戦闘ログを読めます。帰還後は同じ時系列の記録に報酬・戦闘実績・撤退時の観測事実を加えて表示します。編成一覧やダンジョン一覧とは混在しません。パーティタブではどの操作画面でも全隊の残り時間を確認できます。

重複していた「ダンジョン」タブと専用画面は削除しました。ダンジョン選択はパーティの「出撃」から行います。ホームのストーリー導線は、未編成なら「編成」、編成済みなら「出撃」を開きます。探索時間の選択はパーティ・ダンジョンごとにページ内で保持し、メニュー切替・装備変更・編成調整で戻りません。ページ再読み込みで等倍に戻る表示設定で、進行セーブの形式は変更していません。探索中に再読み込みした場合、パーティの初期操作画面は出撃画面になります。戦闘・報酬・解放・自動周回なしの仕様は変更していません。

Web制作スキルに沿い、既存のギルドUIを継承してスマートフォンでは縦配置、隊列ボタンは44px以上の操作領域にしています。`node tests/party-workflow.test.js` で出撃導線、空編成、人数上限、隊列変更、設定の分離、隊別の時間保持、探索中の保護、結果表示、重複出撃を検証します。実ブラウザでの見た目・操作確認は未実施です。

## 全パーティの探索状況一覧

パーティタブの上部に各隊を1行で表示します。隊名・人数・メンバー、未編成／待機／探索中／帰還・待機／未解放、探索先・時間倍率・残り時間・時間経過バーを一覧で確認できます。選択していない隊の残り時間とバーも毎秒更新し、帰還時は前回探索先・成功／撤退・獲得金額を表示します。「帰還・待機」は最新結果がある待機状態で、未読判定ではありません。

各行の「パーティを編成する」「出撃（探索中は探索ログ）」「直近ログ」から操作します。「出撃」は設定済みの攻略先へその場で探索を開始し、別画面へ移動せず、一覧の探索状態だけを更新します。スクロール位置も維持します。直近の探索結果は、成功を緑、撤退を赤の状態表示とカード左端で区別し、獲得した所持金・経験値・装備点数・素材数と代表的な品名を短いチップで確認できます。獲得系スキルで経験値に個人差がある場合は最小値〜最大値を表示します。未編成の隊は出撃不可、記録がない隊は直近ログ不可、未解放の隊は解放条件を表示します。別の隊の帰還で選択中の隊や操作画面を勝手に変更しません。探索中の隊を開くと現在までの探索記録を読め、敵との遭遇行から戦闘ログを展開できます。

「冒険者ギルド物語2」の公開[画面説明](https://wikiwiki.jp/guildmono2/%E7%94%BB%E9%9D%A2%E8%AA%AC%E6%98%8E)と[初心者ガイド](https://wikiwiki.jp/guildmono2/%E5%88%9D%E5%BF%83%E8%80%85%E3%82%AC%E3%82%A4%E3%83%89)にある、各パーティの確認から出撃・探索記録へ進む導線を参考に、既存のギルドUIへ適用しました。画面そのものの複製や画像素材の流用はしていません。Web制作スキルに沿い、スマートフォンでは行を縦配置にします。

## 雇用後のキャラクター画像変更

雇用確認では名前のみ変更でき、画像は応募者の画像をそのまま引き継ぎます。応募時は職業3種・種族3種・生まれ3種の合計9候補から画像を抽選します。雇用後はパーティからキャラクター装備画面を開き、能力と行動率の欄にある画像を約600ms長押しすると、職業・種族・生まれとの一致に関係なく全135画像、物語人物8画像、従来画像8種から変更できます。同じ分類の3画像は、標準型・軽装で動的な若手型・重厚で儀礼的な熟練型という異なる方向に分け、体格・年齢・姿勢・装備・シルエットが重複しにくい構成にしています。

指やマウスを12pxより動かす、押すのをやめる、スクロールする、ポインター操作がキャンセルされる場合は長押しを中止します。画像選択中にキャンセルすると保存せず、保存失敗時には変更を取り消します。探索中も見た目だけ変更でき、能力・装備・出撃済み探索のスナップショットは変わりません。画像変更は共通の操作コマンド経由でlocalStorageへ保存され、書き出し・読み込みにもそのまま含まれます。保存形式は変更していないため初期化は不要です。

画像選択画面は、名称検索、職業／種族／生まれ／物語人物／従来画像の分類、15件単位のページ切り替えに対応しています。現在選択中の画像が属する分類とページを最初に開くため、画像が増えても現在の外見を見失わずに探せます。スマートフォンでは3列表示に固定し、1ページあたりのスクロール量を抑えています。

生成画像135種、物語人物8種、従来画像8種は、元アトラスから `tools/split-portrait-atlases.ps1` で人物領域を抽出した256×384pxの透明PNGとして `assets/characters/individual/` に保存しています。151種すべてを共通の2:3比率で表示し、画面ごとの差は横幅だけで決まります。表示時にアトラスをCSSで切り抜かないため、隣の人物や武器がカードへはみ出さず、足元の位置も一覧・パーティ・装備・募集結果・画像選択で揃います。旧既定画像のまま保存されているNPCは専用画像へ更新し、プレイヤーが手動で選び直した画像は保持します。セーブ初期化は不要です。

Web制作スキルに沿って既存の画像選択UIを再利用しています。`node tests/portrait-edit.test.js` で雇用時の固定画像、長押し・早期解除・移動・スクロール・キャンセル、キーボード、保存・入力検証・保存失敗、編成と能力への影響なしを検証します。実ブラウザ・実機での長押し確認は未実施です。

## 募集のお披露目演出

募集ボタンの成功時に、召喚紋と光粒が浮かぶギルドの門が開き、約2.2秒後に応募者カードが一人ずつ回転して現れます。カードには画像・名前・職業・種族・生まれ・得意分野を表示し、能力欄を横にスクロールするとHP・物理攻撃・物理防御・魔法攻撃・魔法防御・魔法回復・命中・回避・速度・攻撃回数・会心率・重量上限・各種威力倍率をすべて確認できます。各カードの「この冒険者を雇う」から、詳細一覧を経由せず確認画面へ進み、現在の名前と画像のまま雇用できます。名前変更や能力・適性・スキルの比較が必要な場合は「詳細を見る」または「全員の詳細を比較する」を使います。「演出をスキップ」で全員を即時表示し、Escapeでもスキップ／選考画面への移動ができます。音声・有料通貨・新しいレアリティ判定は追加していません。

応募者は演出の開始前に募集処理で抽選・保存します。スキップ・画面移動・ページを閉じる操作で再抽選されず、再起動時は保存済み応募者の選考画面を表示します。連打しても応募者を追加抽選せず、保存に失敗した募集では印章消費を取り消し、演出も開始しません。2〜5人応募・1人雇用・雇用時の画像変更なしの仕様です。

`prefers-reduced-motion` が有効なら導入を省略し、カードのアニメーションも止めて全員を即時表示します。スマートフォンではカードを2列配置にし、画面内をスクロールできます。演出は `js/recruitmentReveal.js` に分離しています。`node tests/recruitment-reveal.test.js` で保存順序、開門タイマー、段階表示、即時雇用、詳細比較、スキップ、演出中断、募集の重複防止、低モーション設定、保存失敗を検証します。保存形式の変更・初期化は不要です。

## 装備変更時の表示維持と能力差分

装備画面で装備・解除を行っても、閲覧していた一覧のスクロール位置を維持します。画面上部には現在重量／最大重量と残り重量を固定表示し、長い能力欄や装備候補を見ている間も重量を確認できます。

変更直後は画面左下に、最大HP・物理／魔法能力・命中・回避・速度・攻撃回数・会心・各種威力・重量のうち実際に変化した項目だけを「変更前 → 変更後」と増減値で表示します。装備スキルや倍率を含む最終能力値を比較し、4.5秒経過するか、装備画面をスクロールすると閉じます。スマートフォンでは下部メニューに重ならない高さへ表示し、通知自体は装備操作を妨げません。

保存データと戦闘計算は変更していないため、セーブ初期化は不要です。`node tests/modal-actions.test.js` で連続装備・スクロール位置復元・重量固定表示・差分通知を、`node tests/party-equipment-ui.test.js` で重量表示を検証します。

## 行動率スライダー

キャラクター装備画面の行動率は、攻撃・技・呪文・回復をそれぞれ独立した0〜100%のスライダーで設定します。雇用時の初期値は4項目すべて100%です。「全100」「物理重視」「魔法重視」「回復重視」のかんたん入力でスライダーをまとめて変更でき、確認してから保存します。4項目の合計値に制限はありません。出撃済みの探索は出撃時の値を保持し、変更は次回出撃から反映されます。

戦闘では行動順を行動速度と小さな乱数で決め、各冒険者の手番に「回復 → 呪文 → 技 → 通常攻撃」の優先順で個別に確率判定します。技・呪文は習得済みかつ同分類の再使用待ちが終わっている場合、回復はさらに生存中の負傷者または解除可能な状態異常がいる場合だけ判定します。使用不能な項目は飛ばし、どの判定にも成功しなかった場合は防御して次に受けるダメージを半減します。
